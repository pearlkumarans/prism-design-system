Data Table

A data table is for browsing many similar things at once — devices, tickets, users, transactions. The toolbar holds filters and global actions, the rows are pickable, and a floating bar appears the moment the user selects something so they can act on the whole selection at once. Use a data table when the user needs to scan, sort, filter, or bulk-edit. For a single record’s details, use a Detail panel instead.

Content GuidelinesRecommended

Do
  • Keep column headers short and noun-based ("Status", "Owner", "Due date").
  • Put the primary link (the row's name / identifier) in the first data column.
  • Align numeric columns to the end of the cell for scannability.
  • Show N Selected and a clear-selection ✕ in the bulk-action bar.
  • Pair an empty state with a clear next action ("Add your first device").
Don't
  • Write sentence-long headers — they break the column rhythm.
  • Left-align numbers — they become hard to compare.
  • Attach Delete to a per-row icon when the same action works in bulk.
  • Cram every action into the main toolbar — it becomes noisy.
  • Render a blank table with no guidance when empty.

When and Where to Use

Data Table is designed for structured, record-based data that users need to scan, sort, select, and act on.

When to use

  • For structured, record-based data (tickets, devices, users, assets, incidents).
  • When bulk actions (delete many, export many) are a core workflow.
  • When users compare rows on multiple attributes and column alignment is essential.
  • When per-row detail is deep enough that clicking a row should open a drawer or detail page.

When NOT to use

  • Small static lists with 3–7 simple items — use a plain list.
  • Hierarchical / tree data — use a tree view or expandable rows.
  • Card-based content with rich imagery — use a card grid.
  • Dashboards of single values — use widgets / metric cards, not a table.

Complete Do's and Don'ts

Guidelines for effective Data Table usage.

Do
  • Short headers: Keep column headers short and noun-based ("Status", "Owner", "Due date").
  • Numeric alignment: Align numeric columns to the end of the cell.
  • Primary link first: Put the primary link (row's name / identifier) in the first data column.
  • Bulk destructive actions: Use the Selected variant's bulk-action bar for destructive actions (with confirmation).
  • Selection counter: Show 'N Selected' and a clear-selection ✕ in the bulk-action bar.
  • Overflow menu: Use ⋮ for column chooser, density, export-all, and low-frequency actions.
  • Sticky header: Sticky the header row when the table scrolls.
  • Empty state CTA: Pair an empty state with a clear next action ("Add your first device").
  • Consistent height: Keep row height consistent within a single table.
Don't
  • Sentence headers: Write sentence-long headers.
  • Left-align numbers: Left-align numbers — they become hard to compare.
  • Buried primary link: Bury the primary link mid-row.
  • Per-row delete: Attach Delete to a per-row icon when the same action works in bulk.
  • Stale bulk bar: Leave the bulk bar visible when no rows are selected.
  • Crowded toolbar: Cram every action into the main toolbar — it becomes noisy.
  • Scrolling header: Let the header scroll away — users lose context.
  • Blank empty table: Render a blank table with no guidance when empty.
  • Mixed heights: Mix row heights based on content length.

HTML Structure

The semantic base: a <table> with proper <thead> / <tbody>, scope attributes on headers, and ARIA hooks for bulk actions.

<div class="dt-wrapper">
  <div class="dt-toolbar">
    <!-- search input + filter button + overflow menu -->
  </div>
  <table role="table">
    <thead>
      <tr>
        <th scope="col">
          <input type="checkbox" aria-label="Select all rows"/>
        </th>
        <th scope="col">Name</th>
      </tr>
    </thead>
    <tbody>
      <tr>
        <td><input type="checkbox" aria-label="Select row 1"/></td>
        <th scope="row"><a>MacBook-Pro-14</a></th>
      </tr>
    </tbody>
  </table>
  <div class="dt-footer">...</div>
  <div class="dt-bulk-bar" role="region" aria-label="Bulk actions">...</div>
</div>

JS pattern: select-all / indeterminate

function syncSelection() {
  const rowChecks = document.querySelectorAll('.dt-row-check');
  const head      = document.querySelector('#dt-head-check');
  const checked   = [...rowChecks].filter(cb => cb.checked);
  if (checked.length === 0)            { head.checked = false; head.indeterminate = false; }
  else if (checked.length === rowChecks.length) { head.checked = true;  head.indeterminate = false; }
  else                                          { head.checked = false; head.indeterminate = true;  }
  document.getElementById('dt-bulk-bar').classList.toggle('visible', checked.length > 0);
}

Accessibility

Guidelines for ensuring Data Table is accessible across assistive technologies, keyboard, and screen readers.

Keyboard Navigation

ActionResult
TabEnters the table; moves focus to the next interactive element (checkbox, link, button).
Arrow keys (grid mode)Move focus between cells.
SpaceToggles row selection when focus is on a row checkbox.
Shift+ArrowExtends selection to adjacent rows.
⌘/Ctrl+ASelects all visible rows.
EnterActivates the primary link in the focused cell.
EscapeClears selection and closes the bulk-action bar.
PageUp / PageDownAdvance pagination one step.

Keyboard users must always be able to reach the bulk-action bar via Tab from the last selected row — never trap focus inside the table body.

ARIA Attributes & Semantics

  • Element: Use a proper <table> with <thead>, <tbody>, <tr>, <th scope="col">, <td>.
  • Virtualized grid: If built from <div>s, expose grid roles: role="grid", role="row", role="columnheader", role="gridcell".
  • Row checkbox: Each row checkbox has aria-label="Select row N" (or row identifier).
  • Header checkbox: aria-label="Select all rows" + aria-checked="mixed" when selection is partial.
  • Sort: Sortable headers expose aria-sort="ascending", "descending", or "none".
  • Row headers: If the first data column is the row's primary identifier, mark those cells with <th scope="row">.
  • Bulk bar: Render as role="region" aria-label="Bulk actions" so it is announced when it appears.
  • Loading: Set aria-busy="true" on the <table> while the skeleton renders.
  • Empty state: Wrap in role="status".

Screen Reader Guidance

  • Column context: <th scope="col"> causes assistive tech to announce the column name when reading each cell.
  • Live updates: On filter / sort / pagination, announce the new range via an aria-live="polite" visually-hidden status node — e.g. "Showing 1 to 20 of 243".
  • Selection count: When the bulk bar appears, the counter ("3 Selected") should be in a live region so the selection delta is announced.
  • Destructive actions: Follow Delete with a confirmation dialog — never delete straight from the bulk bar.
  • Pagination: Previous / Next buttons must expose their state via disabled when at the boundary, not just grey styling.

Focus Management

  • Visible focus ring: Each interactive cell (checkbox, link, per-row icon button) must have a visible 2px focus ring. Never remove :focus-visible outlines without replacement.
  • Bulk bar focus: When the bulk bar appears, focus remains on the last-checked row checkbox. Users Tab forward to reach the bulk actions.
  • Row delete: After deleting rows via bulk action, move focus to a sensible next element — the toolbar or the first remaining row — never leave focus on a detached node.
  • Pagination: After Previous / Next, keep focus on the same button (so repeated paging works). Announce the new page via aria-live.
  • RTL: Column order and toolbar mirror in RTL. Pagination arrows swap visually but keep their logical meaning.

Checkboxes and per-row action icons must provide an effective 44px touch area. For Compact density, rely on the full row being clickable to expand the hit area.
