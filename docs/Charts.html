Charts

The Chart (<ds-chart>) is a data-visualization primitive covering 9 types across 4 families — column / bar (single, grouped, stacked), line, pie / donut / funnel, and gauge. It renders gridlines, axes, series, and an optional legend as a self-contained SVG, themed entirely from the chart tokens so it re-themes across light / dark / night / green. It is bare by design — no header, surface, or padding — because it lives inside a host widget that owns the chrome. ds-chart owns only a loading skeleton; empty and error states belong to the host.

Content GuidelinesRecommended

Do
  • Pick the type by intent — bar/column for comparison, line for trend, pie/donut for part-to-whole, gauge for a single value.
  • Keep series to ≤7 so the categorical palette doesn't repeat.
  • Label both axes and keep the value axis anchored at 0.
  • Let the host widget own the header, surface, and empty/error states.
  • Provide real data via the JS property; rely on the token theme for color.
Don't
  • Use more than 7 categorical colors — switch to a sequential ramp instead.
  • Use 3-D, truncated axes, or distorted aspect ratios.
  • Hardcode series colors — use the chart tokens so it re-themes.
  • Rely on color alone to convey meaning — pair with labels.
  • Render an empty/error placeholder inside the chart — that's the widget's job.

Usage

Which chart type to reach for, and how the chart shares responsibility with its host widget.

When to use each type

IntentTypeNotes
Compare categoriesbar / columnUse grouped for side-by-side series, stacked for part-of-total within a category. Switch to bar for long category labels.
Show a trend over timelineContinuous data across an ordered axis; supports multiple series.
Part-to-wholepie / donut / funnelFew slices (≤6). donut shows a center total; funnel for stage drop-off.
A single value vs. a targetgaugeOne 0–100 value with a label (e.g. capacity, completion).

State ownership

The host widget owns the data lifecycle. Empty and error states are rendered by the widget using the system Empty state component — consistently across all widget content (chart, table, KPI). ds-chart owns only the loading skeleton; it never draws an empty or error placeholder itself.

Do & Don't

Do
  • Keep series to ≤7 so categorical colors stay distinct.
  • Label both axes and use the categorical palette in order.
  • Anchor the value axis at 0; use bar for long labels.
  • Let the host widget render empty/error via the Empty state.
Don't
  • Use more than 7 categorical colors at once.
  • Use 3-D effects or distorted aspect ratios.
  • Truncate the value axis — it misrepresents magnitude.
  • Rely on color as the only signal.

Install & usage

Register the component, then drive it with attributes and the data property. Source: design-system-library/src/components/chart/chart.js.

Register the component

JS
<script type="module" src="design-system-library/src/components/chart/chart.js"></script>

Basic markup

Ships with sample data, so it renders standalone — place it inside a widget that owns the surface.

HTML
<ds-chart type="column" mode="grouped"></ds-chart>

Setting data (cartesian)

JS
const chart = document.querySelector('#sales');
chart.data = {
  categories: ['Q1', 'Q2', 'Q3', 'Q4'],
  series: [
    { name: 'Revenue', values: [42, 58, 50, 71] },
    { name: 'Profit',  values: [22, 30, 28, 45] },
  ],
};

Per-type data

JS
// Pie / donut / funnel — first series' values are the slices
chart.data = {
  categories: ['Direct', 'Organic', 'Referral'],
  series: [{ name: 'Sessions', values: [38, 27, 18] }],
};

// Gauge — a single 0–100 value + label
chart.data = { value: 68, label: 'Capacity' };

Theme note

All colors are token-driven — never hardcode series hues. The chart reads from --uems-bg-chart-*, --uems-border-*, and --uems-text-*, so it re-themes automatically.

Accessibility

Guidelines for an accessible Chart across assistive tech and input methods.

Roles & ARIA

ConcernImplementation
RoleThe chart container has role="img" with an aria-label summarizing the data (e.g. "column chart, 3 series, categories: Q1, Q2, Q3, Q4").
Data-table fallbackA visually-hidden <table> mirrors the real data behind the chart for screen readers (with <caption> and row/column headers).
SVGThe drawn SVG is aria-hidden="true" / focusable="false" — meaning is carried by the label + table.
LoadingWhile loading, the container sets aria-busy="true" and aria-label="Loading chart".

Keyboard & focus

Key / actionBehavior
Legend itemsReal <button>s — Tab to focus, Enter / Space to toggle the series. aria-pressed reflects on/off.
Focus ringLegend buttons show a visible :focus-visible outline.
TooltipHover-only; its content is also in the hidden data table so it isn't AT-only on hover.

Other concerns

ConcernRequirement
Color not the sole signalPair color with labels / values; never rely on hue alone to convey meaning (e.g. positive vs. negative).
ContrastAxis / tick labels use --uems-text-tertiary on the surface and meet WCAG 2.1 AA.
Reduced motionprefers-reduced-motion: reduce disables the bar grow, line draw, and arc sweep entrance animations.
RTLrtl (or host dir="rtl") mirrors the axis side, legend alignment, and label direction.
