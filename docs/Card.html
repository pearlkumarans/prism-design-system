Card

A generic content surface — the "everything container" of the system. Swap type for the surface treatment (elevated, outlined, filled, plain), drop anything into the default slot for the body (text, a stat, a mini chart, a list, or a full <ds-chart>), and <ds-card> becomes a KPI card, a settings panel, a list card, or a chart card from the same component. It's a self-contained surface — it owns its own background, border/shadow, and radius — the same contract as ds-kpi-card.

Anatomy

A live <ds-card> (elevated, medium) with its parts called out. The card owns its surface — radius 16, per-type background/border/shadow — the host only sizes it.

When to use

  • Any dashboard tile that needs a title + swappable body — a stat, a chart, a list, or a table.
  • A settings panel or grouped-content section that needs a labeled surface with an optional footer action.
  • A selectable item in a card grid/picker — use selected for the chosen state, driven by the parent list, not by the card itself.

When not to use

  • A dedicated metric tile with a fixed value+trend+gauge composition — use ds-kpi-card instead, which is purpose-built for that and needs less markup.
  • A clickable navigation tile where the whole card should behave like a button/link with its own focus ring — wrap ds-card in a real <a>/<button> rather than trying to make the card itself interactive.

Content-slot markup patterns

These are plain markup conventions for the default slot — not separate custom elements. Match the typography/tokens shown for a consistent look.

Stat pattern
HTML
<ds-card title="Missing Patches" subtitle="Devices requiring updates" footer-label="View devices">
  <div>
    <div style="font-size:16px;font-weight:700;">587</div>
    <div style="font-size:12px;color:var(--uems-text-secondary);">Missing patches</div>
    <div style="font-size:14px;font-weight:500;color:var(--uems-text-accent);">+12% vs last week</div>
  </div>
</ds-card>
Real chart pattern
HTML
<ds-card title="Weekly Activity" subtitle="Logins over the last 7 days">
  <ds-chart type="line" show-legend="false"></ds-chart>
</ds-card>

RTL

Header and Footer are plain flex rows — dir="rtl" mirrors them for free (title/header-action swap sides, footer link moves to the visual left). No duplicate content props needed.

dir="rtl"

Basic usage

HTML
<ds-card
  type="elevated"              <!-- elevated | outlined | filled | plain -->
  size="medium"                <!-- small | medium | large -->
  title="Card title"
  subtitle="Supporting subtitle"
  leading-icon="info-circle"   <!-- badge, on by default -->
  footer-label="Action" footer-href="#"
  dir="rtl">
  <!-- header action renders a <ds-icon-button> automatically; -->
  <!-- slot="header-action" to override, default slot for the body -->
</ds-card>

Roles & semantics

  • Card root has no implicit interactive role — it's a static container (role="group" with an aria-label derived from title when set).
  • Header action and footer link are real <button>/<a> elements with their own focus rings — never a styled <div>.
  • selected should also be exposed via aria-selected="true" on the host when used in a selectable-list context (e.g. a parent with role="listbox") — the ring color alone isn't sufficient for screen readers.

Keyboard

KeyAction
TabMoves focus to the header action button, then the footer link, then any focusable content in the Body slot — in DOM order.
Enter / SpaceActivates whichever button/link is focused. The card frame itself is never a tab stop.

Contrast & RTL

  • All text tokens (Text-Primary, Text-Secondary) meet AA on every type's background, including Filled's tinted surface.
  • disabled's 0.5 opacity is applied to the whole card — verify the Selected ring still reads against a light page background when both are set together.
  • dir="rtl" mirrors layout and focus order — the footer link moves to the visual left, matching reading order.
