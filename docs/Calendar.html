Calendar

A calendar is the floating panel that opens when the user wants to pick a date by clicking instead of typing — a delivery date, a meeting day, a vacation range. Use it whenever the date matters to the user as a position in a week or month, not just a number. For typing in a known date, pair it with a Date picker; for relative ranges (last 7 days, this quarter), use a preset dropdown.

Content GuidelinesRecommended

Do
  • Close the calendar popover immediately on day click for Single selection.
  • Show the Footer Actions for Range selection so the user can confirm or cancel.
  • Disable past dates when only future dates are valid (e.g. booking, scheduling).
  • Keep the calendar panel above or below the trigger field, with arrow/popover positioning.
  • Pre-populate the calendar with the current date or last-used date.
Don't
  • Require a separate "Apply" step for single date selection unless the UI context demands it.
  • Auto-close a range picker on end-date click without giving the user a chance to review.
  • Show disabled dates without a clear visual or accessible reason.
  • Clip the calendar behind other elements or off-screen edges.
  • Open the calendar on an arbitrary month with no selection context.

RTL (Right-to-Left)

In Arabic, Hebrew, and other RTL locales the calendar mirrors so weekday order, month-navigation chevrons, and selection range direction all reverse to feel native.

LTR (default)
  • Weekday order: Sun → Sat
  • Previous month: chevron left
  • Next month: chevron right
  • Range fill: grows start → end left-to-right
  • Footer actions: Cancel left, Apply right
RTL
  • Weekday order: Sat → Sun (visually mirrored)
  • Previous month: chevron right
  • Next month: chevron left
  • Range fill: grows right-to-left
  • Footer actions: Apply left, Cancel right

How it works: set dir="rtl" on the calendar element (or pass the rtl attribute on <ds-calendar>). The grid uses CSS direction: rtl so weekday headers and date cells render right-to-left; navigation chevrons are mirrored via [dir="rtl"] selectors in calendar.css. Locale-aware date formatting (Hijri, Persian) is left to consuming code — the visual chrome is direction-only.

When and Where to Use

Guidelines for choosing and applying the Calendar component in your interfaces.

When to use

  • When the user must select a specific calendar date (e.g. scheduled task, report date, event date).
  • When the user must select a date range (e.g. booking period, filter window) — use Type=Range.
  • Inside date input fields — the calendar appears as a popover triggered by clicking or focusing a date input.
  • For reporting filters or query date ranges where two-month visibility helps compare periods.

When NOT to use

  • For selecting a time-of-day — combine with a Time Picker; do not use the Calendar alone.
  • For relative date presets ("Last 7 days", "This month") — use a dropdown filter instead.
  • When only a year or month needs to be selected — use a simpler Month/Year picker.
  • Inline/always-visible calendar for displaying events — use a full Calendar View component instead.

Single vs Range

Choose the right calendar type based on the selection scenario.

ScenarioUse
Picking one specific date (e.g. due date, birthdate)Single
Picking a start and end boundary (e.g. leave dates, report window)Range
User may clear or leave date unsetSingle with an optional clear action in the footer

Do's and Don'ts

Guidelines for effective Calendar usage.

Do
  • Immediate selection: Close the calendar popover immediately on day click for Single selection.
  • Confirm ranges: Show the Footer Actions for Range selection so the user can confirm or cancel.
  • Disable invalid dates: Disable past dates when only future dates are valid (e.g. booking, scheduling).
  • Smart positioning: Keep the calendar panel above or below the trigger field, with arrow/popover positioning.
  • Pre-populate: Pre-populate the calendar with the current date or last-used date.
Don't
  • Extra confirm step: Require a separate "Apply" step for single date selection unless the UI context demands it.
  • Auto-close range: Auto-close a range picker on end-date click without giving the user a chance to review.
  • Unclear disabled: Show disabled dates without a clear visual or accessible reason.
  • Clipping: Clip the calendar behind other elements or off-screen edges.
  • No context: Open the calendar on an arbitrary month with no selection context.

Accessibility

Guidelines for ensuring the Calendar component is accessible across assistive technologies and input methods.

Keyboard Interaction

KeyAction
TabMove focus between navigation arrows, day cells, and footer buttons.
← / →Move focus one day left / right within the grid.
↑ / ↓Move focus one week up / down.
Page UpNavigate to the previous month.
Page DownNavigate to the next month.
HomeMove focus to the first day of the current week.
EndMove focus to the last day of the current week.
Enter / SpaceSelect the focused date (or set range start/end).
EscapeClose the calendar popover without committing the selection.

ARIA Attributes & Screen Reader Guidance

  • Role: Wrap the calendar in role="dialog" with aria-modal="true" and aria-label when it appears as a popover.
  • Grid semantics: Use role="grid" on the date area, role="row" on each week row, role="gridcell" on each day cell.
  • Weekday headers: Mark with role="columnheader" and full-name aria-label (e.g. aria-label="Sunday") — abbreviations alone are ambiguous.
  • Selected date: Use aria-selected="true" on the active day cell.
  • Range selection: For range start: aria-selected="true" + aria-label="March 9, start of range". For end: similar. For in-between: aria-label="March 10, in selected range".
  • Navigation: Month/year display should have aria-live="polite" to announce month changes when arrows are clicked.
  • Disabled dates: Use aria-disabled="true" and tabindex="-1" — do not remove from DOM so screen readers can encounter them.
  • Escape: Must close the calendar popover and return focus to the trigger field.

Focus Management

  • On open: Focus the selected date (or today if no selection). This ensures keyboard users can immediately navigate.
  • On close (Escape / Apply): Return focus to the trigger input field to maintain context.
  • Single active cell: Only one day cell receives tabindex="0"; all other cells use tabindex="-1". Arrow keys move the roving focus.
