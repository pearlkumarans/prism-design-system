Tooltip

A tooltip is the short bubble that appears when the user hovers or keyboard-focuses a control — the full name behind a truncated label, the keyboard shortcut for a button, the meaning of an icon. Keep it under 80 characters and never put critical info there: touch users can’t hover. For more than one line of explanation, use a Popover.

Content GuidelinesRecommended

Do
  • Keep tooltip text concise — 1–2 short sentences maximum.
  • Use Show Icon=OFF when the icon is redundant with the trigger icon.
  • Set the correct Position so the arrow always points at the trigger.
  • Use RTL=true for Arabic/Hebrew content.
  • Dismiss on Escape and when focus leaves the trigger.
Don't
  • Use a tooltip to display data tables, images, or interactive elements.
  • Show the icon when it adds no meaning beyond the text.
  • Use without arrow in contexts where the tooltip appears far from the trigger.
  • Use the LTR label for RTL text — it will be left-aligned and feel incorrect.
  • Keep the tooltip visible after the user interacts with another element.

When and Where to Use

Guidelines for when a Tooltip is the right pattern.

When to use

  • To clarify the purpose of icon-only buttons, controls, or form labels where space doesn't allow inline text.
  • To surface secondary, supplementary information that shouldn't permanently occupy space in the layout.
  • To explain why a control is disabled (use red theme for destructive or error context).
  • For keyboard and screen reader users as an accessible label for non-text interactive elements.

When NOT to use

  • For interactive content (links, buttons inside the tooltip) — use a Popover instead.
  • For lengthy explanations (> 2–3 lines) — consider an inline help text or a modal.
  • As the sole label for a control — the underlying element must still have an aria-label or visible label.
  • For error messages on form fields — use an inline validation message below the field instead.

Choosing a Theme

Match the tooltip theme to the surrounding UI surface.

ScenarioTheme
General informational context on a light UI surfacedark
UI surface is dark or mid-tone (e.g. dark sidebar, header)light
Explaining an error, destructive action, or blocked statered

Choosing a Position

Position guidance for common trigger placements.

  • Prefer up center or down center for most inline triggers — they are the most predictable.
  • Use right or left when the trigger is at the top/bottom edge of the viewport.
  • Use without arrow only when the tooltip is positioned by a layout constraint and the visual connection to the trigger is already clear.
  • Avoid up left / up right unless you need to anchor to a specific corner of a wide trigger.

RTL Support

When RTL=true, the tooltip renders Arabic text right-aligned. The icon remains on the left of the layout direction.

RTL Preview

  • RTL content uses the Tooltip Label RTL text property (independent of LTR content).
  • The arrow flips horizontally for left/right positions to maintain directional consistency.
  • Set dir="rtl" on the tooltip container (or a parent) for Arabic/Hebrew content.

Positioning Pattern (JavaScript)

function showTooltip(trigger, tooltip, position = 'up-center') {
  const triggerRect = trigger.getBoundingClientRect();
  const tooltipRect = tooltip.getBoundingClientRect();
  const gap = 8; // px between arrow tip and trigger edge

  // Example: up-center
  const top = triggerRect.top - tooltipRect.height - gap;
  const left = triggerRect.left + triggerRect.width / 2 - tooltipRect.width / 2;

  tooltip.style.top = `${top + window.scrollY}px`;
  tooltip.style.left = `${left + window.scrollX}px`;
  tooltip.setAttribute('aria-hidden', 'false');
  tooltip.classList.add('is-visible');
}

Note: Use a dedicated positioning library (Floating UI / Popper.js) for production — they handle viewport clipping, scroll containers, and automatic flip/shift.

Accessibility

Guidelines for ensuring Tooltip is accessible across assistive technologies and input methods.

Keyboard Interaction

TriggerTooltip Action
Tab / focus enters the triggerTooltip appears
EscapeTooltip dismisses immediately
Focus leaves trigger (blur)Tooltip dismisses with delay (300ms recommended)
Hover on triggerTooltip appears (200ms delay recommended)
Hover leaves triggerTooltip dismisses (150ms delay recommended)

Tooltips triggered by hover must also be triggerable by keyboard focus — they are not mutually exclusive.

ARIA Attributes & Screen Reader Guidance

  • Role: Always use role="tooltip" on the tooltip container.
  • Association: Connect trigger to tooltip via aria-describedby="[tooltip-id]". Use aria-label or aria-labelledby on the trigger if it has no visible text.
  • Hidden state: Set aria-hidden="true" when the tooltip is not visible; "false" when shown.
  • Keyboard trigger: Tooltip must appear on :focus — not hover only.
  • Escape: Escape key must dismiss the tooltip without moving focus.
  • Persistent on hover: The tooltip itself must be hoverable (pointer-events) so users can copy text or reach a scrollbar.
  • RTL: Set dir="rtl" on the tooltip container (or a parent) for Arabic/Hebrew content.
  • Icon: Icon must be aria-hidden="true" — the text already conveys the full meaning.
  • No interactive content: Do not place buttons, links, or inputs inside a role="tooltip" — use a Popover for interactive overlays.

Focus State

  • Visible focus indicator: The trigger element that activates the tooltip must have a clearly visible focus ring (WCAG 2.4.7).
  • Focus does not auto-move: When the tooltip appears, focus stays on the trigger element. The tooltip is not focusable itself.
  • Escape behavior: Pressing Escape dismisses the tooltip without moving focus away from the trigger.
