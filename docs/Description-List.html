Description list

A description list presents structured term → value pairs — metadata like status, owner, or dates on detail pages, side panels, and spec sheets. It maps to the native <dl> element. Pick how many columns the pairs flow into (1–3) and whether each item is Stacked (term above value) or Horizontal (term beside value). Based on PatternFly’s Description List.

Anatomy

1
List (<dl>)The container. Holds every term/value pair and owns the padding and column layout.
2
ItemOne term/value pair. Never splits across a column boundary.
3
Term (<dt>)The label/key. Text-Secondary, 12/16 semibold.
4
Value (<dd>)The value. Text-Primary, 14/20 regular. Empty values render an em-dash.
5
Help iconOptional. Shown when the item has help text; hover for a tooltip.
6
Edit buttonOptional. A full Icon Button shown when the item is editable.

When to Use

  • Use for read-only metadata on detail pages, side panels, drawers, and spec sheets — status, owner, timestamps, IDs.
  • Don’t use for editable forms — use Text field / Input select. (Individual values may offer an inline edit affordance that opens an editor.)
  • Don’t use for rows of homogeneous records — use a Data table.

Columns & orientation

ChoiceBest for
1 columnNarrow panels, modals, drawers
2 columnsMedium-width detail pages
3 columnsWide spec sheets
StackedNarrow items / unpredictable term lengths (term above value)
HorizontalWide items with short, consistent terms (fixed 140px term column, values align)
Horizontal‑autoCompact inline pairs where the term should hug its text and values need not align to a column

Responsive

  • As width narrows, collapse to a single column and switch to Stacked orientation (below ~768px). The fixed 140px term column can’t stay side-by-side on small screens.
  • The component keeps a single logical <dl> and drops to one column via CSS — no markup restructuring.

RTL Support

Set rtl to mirror the layout: column reading order reverses and the help icon / edit button swap sides. Provide already-localized term / description strings.

HTML + JS

Usage

Set attributes for layout; pass the pairs via the items JS property.

<ds-description-list columns="2" orientation="horizontal"></ds-description-list>

<script>
  document.querySelector('ds-description-list').items = [
    { term: 'Status',  description: 'Active' },
    { term: 'Owner',   description: 'Jane Doe', help: 'Billing owner', editable: true },
    { term: 'Region',  description: '' },  /* empty → em-dash */
  ];
  document.querySelector('ds-description-list')
    .addEventListener('ds-description-list-edit', e => console.log(e.detail));
</script>

Accessibility

The component renders semantic <dl> / <dt> / <dd>, so the term/value association is conveyed natively.

  • Multi-column is a visual arrangement only — it stays a single logical <dl> (columns via CSS), so screen readers still pair each term with its value.
  • DOM order = logical order (term, its help button, value, edit button), item by item. RTL reverses the visual order via dir="rtl"; the DOM order stays logical.
  • The help icon is a <button> with an aria-label (e.g. “About {term}”).
  • The edit button is a full Icon Button with a descriptive aria-label (e.g. “Edit {term}”) — the icon alone is not the accessible name.
  • Contrast: Term #2A303D and Value #15181E on the base surface both exceed WCAG AA for normal text.
