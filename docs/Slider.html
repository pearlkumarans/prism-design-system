Slider

Drag a handle along a track to pick a value — volume, brightness, price, timeout, anything that lives between a known minimum and maximum. Use a slider when the user adjusts by feel and reads the exact number after, not the other way around. Choose Single for one value, Range for a start-and-end pair.

Anatomy

A label and value badge sit above the track. The thumb slides across the track and the filled portion shows where it is. Min/max labels and helper text below are optional — add them when the scale or unit isn’t obvious.

Content GuidelinesRecommended

Do
  • Keep the value badge visible — the user shouldn’t have to guess what they just set.
  • Show min and max labels whenever the unit isn’t obvious (“0%” / “100%”, “Low” / “High”, “$0” / “$500”).
  • Turn on step markers only when there are 10 or fewer discrete steps — otherwise the track looks busy.
  • Use a Range slider for paired bounds (price $10–$500, age 18–65) so the user understands them as one filter, not two.
  • Write helper text that says the unit or the trade-off, not what the control is (“Higher values use more memory”).
Don't
  • Hide the value when the exact number matters (timeouts, prices, retries).
  • Show step markers on a 0–100 slider — the dots overwhelm the track.
  • Use two separate sliders to express one range — use a Range slider.
  • Fire an API call on every drag tick. Wait for the user to release the thumb, or debounce.
  • Use a slider when the user needs to type a precise number — use a number field instead.

RTL (Right-to-Left)

In Arabic, Hebrew, and Persian layouts the slider mirrors itself: the minimum value sits on the right and the user drags right-to-left to increase it. Set dir="rtl" on any ancestor — you don’t need to change the slider.

LTR (default)
  • Min label: left
  • Max label: right
  • Filled track: grows from left to right
  • Arrow keys: Right → increase
RTL
  • Min label: right
  • Max label: left
  • Filled track: grows from right to left
  • Arrow keys: Left → increase (mirrored by browser)

For engineers: the slider uses CSS logical properties (inset-inline-start) so the entire control mirrors as soon as an ancestor sets dir="rtl" — no JavaScript and no extra props. The browser also flips arrow-key direction in RTL contexts, so the keyboard stays consistent with how the track reads.

When and Where to Use

A slider is the right pick when the user adjusts a numeric value by feel — not when they need to type an exact number.

When to use

  • The value lives between a clear minimum and maximum — volume, brightness, price, opacity, percentage.
  • The user dials in by feel and reads the exact number afterwards from the value badge.
  • The range is continuous, or has too many discrete steps to fit as buttons or a dropdown.
  • The user needs to pick a start and an end together (price $10–$500, age 18–65) — use a Range slider.

When NOT to use

  • The user has to enter an exact number (port, year, transaction amount) — use a number field.
  • There are only a handful of named options (Low / Medium / High, S / M / L) — use radios or a dropdown.
  • The user picks small whole-number quantities (1–10 items in a cart) — a stepper with + / − buttons is faster.
  • You need a vertical track — this component is horizontal only.

Complete Do's and Don'ts

Specific guidance — when each option helps the user and when it gets in their way.

Do
  • Keep the value visible: The user has to see the number they just set, not guess it from the thumb position.
  • Anchor the scale with min and max labels: So “Quality” reads clearly as Low–High and not 1–5.
  • Step markers only for short scales: Up to about 10 stops. Beyond that the dots clutter the track.
  • Spell out units and trade-offs in helper text: “Values in GB”, “Higher concurrency uses more memory.”
  • Use Range for paired bounds: Price $10–$500, dates, age brackets — one control, not two sliders.
  • Pick the size by surface: Medium for standard forms, Large for touch and mobile, Small only in dense panels.
  • Match step to user intent: If users think in $5 jumps, set step="5" — not 1.
  • Save the network call for drag end: Listen to ds-slider-change, not every ds-slider-input tick.
Don't
  • Don’t hide the value badge when the exact number matters (timeouts, prices, retries).
  • Don’t crowd a continuous track with step markers — on a 0–100 slider they read as noise, not guidance.
  • Don’t leave the unit ambiguous. “50” could mean percent, seconds, or megabytes — say which.
  • Don’t fake a range with two sliders. The user has to mentally pair them; a Range slider does it for them.
  • Don’t use Small on touch. A 16 px thumb is hard to grab with a thumb tip — Large is built for that.
  • Don’t set step="1" on 0–10,000. Pick a step that matches how the user thinks (100, 250, 500).
  • Don’t hit the API on every drag tick. You’ll send dozens of requests in one drag — debounce or wait for release.

Accessibility

Everything below is already wired into the component — this section explains what your users get, and what you need to provide when you embed the slider.

Keyboard Interaction

KeyAction
TabFocuses the thumb. On a Range slider, Tab again moves to the second thumb.
Arrow Left / DownDrops the value by one step.
Arrow Right / UpRaises the value by one step.
HomeJumps to the minimum.
EndJumps to the maximum.

Semantic HTML

  • Native range under the hood: the slider wraps a real <input type="range">, so screen readers announce it correctly and keyboard controls work without extra code.
  • Label is wired automatically: the visible label prop is connected to the underlying input via for/id. You don’t need to write your own <label>.
  • Range sliders use two inputs: each thumb is its own range input with its own aria-valuemin, aria-valuemax, aria-valuenow — both are tied to a single visible label via aria-labelledby.

ARIA Attributes & Screen Reader Guidance

  • aria-valuenow: updated on every thumb move so screen readers announce the current number.
  • aria-valuemin / aria-valuemax: mirror the min / max props so the user hears the full range, not just the current value.
  • aria-valuetext: if your scale isn’t numeric (Low / Medium / High, Slow / Fast), pass aria-valuetext so screen readers speak the friendly word instead of “3”.
  • aria-describedby: any helper text is automatically linked to the input, so the description is announced together with the value.
  • aria-invalid: set to "true" automatically whenever state="error" is on, so assistive tech reads the slider as invalid.

Focus State Design

  • Visible focus ring: a 2 px accent ring appears the moment a keyboard user reaches the thumb. Never remove it — that’s how keyboard users know which control they’re driving.
  • Ring matches thumb: 24, 28, or 32 px to match Small / Medium / Large — so the ring sits flush around the handle at every size.
  • Step markers: if you show them, give each marker an aria-label or visually-hidden caption so screen readers can call out the steps too.

Disabled State

  • Sets disabled on the underlying range input, so the slider is skipped by Tab and ignored by screen readers as an interactive control.
  • Track, thumb, label, and helper all dim together so the user can see at a glance that this control isn’t live right now.
  • Whenever you disable a slider, tell the user why in the helper text (“Upgrade your plan to change this”). A grey slider with no explanation feels broken.
