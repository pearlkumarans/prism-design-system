Time Picker

A time picker lets people set a time of day — type it directly (9:30 pm, 930, 14:00) or pick from a stepped list. Use the list variant for scheduling and forms; the inline segmented variant for dense, keyboard-first entry. Values are stored locale-independent as 24-hour HH:mm.

Anatomy

The time picker input is composed of three numbered regions. Each label is anchored to the live preview with a connector line.

Content GuidelinesRecommended

Do
  • Set step to the scheduling granularity (5, 15, 30, 60 min) so the list matches the task.
  • Use hour-cycle="24" for infra, logs, and cron-style entry.
  • Give min / max bounds for constrained windows (business hours, maintenance slots).
  • Let people type — the list field parses "9:30 pm", "930", "14:00" forgivingly.
  • Reach for the inline variant when entry is dense and keyboard-first.
  • Announce the selected time via aria-live on change.
Don't
  • Use it for durations (e.g. "45 minutes") — that's a number field, not a time of day.
  • Hand-roll AM/PM toggles beside a plain text input — use the built-in hour-cycle.
  • Store display strings — the value is always locale-independent 24h HH:mm.
  • Set a tiny step (e.g. 1 min) when the list would scroll endlessly — let users type instead.
  • Reject a typed time silently — surface an error with a clear message.
  • Leave the popover open after a selection — the user has moved on.

Popover list icons

The listbox is text-first — each row is a formatted time. Keep icons minimal so scanning stays fast:

  • clock — optional marker on the pinned "Now" row (show-now).
  • check — the selected row; everything else is unadorned.

Rule of thumb: the clock icon identifies the picker. Inside the list, only the selected row and the Now row carry an icon — every other row is plain text. In the inline variant, the chevron steppers are the only icons.

When and Where to Use

Time Picker is designed for choosing a time of day — typed directly or picked from a stepped list.

When to use

  • When users must set a specific time of day (appointment, reminder, deploy window start).
  • When times fall on a regular grid → set step to the scheduling granularity.
  • When entry is dense and keyboard-first → use variant="inline".
  • When infra / logs need 24-hour times → set hour-cycle="24".

When NOT to use

  • For a duration ("45 minutes", "2 hours") — use a number field, not a time of day.
  • For a calendar date — use the Date Picker (pair the two for date + time).
  • For free-form text times in prose — use a plain Text Input.
  • For picking multiple discrete times at once — use a repeatable field group.

List vs Inline

Pick the variant based on how people will enter the time.

VariantBehaviourWhen to pick
listEditable trigger + popover listbox of stepped times. Discoverable options; the field still accepts free typing.Scheduling and forms; when a set of preset times covers most cases.
inlineSegmented HH : MM (AM/PM) field with per-key spin editing and ▲▼ steppers. No popover.Dense, keyboard-first entry where the user already knows the exact time.

Typing vs Picking

The list field is a real editable combobox — the popover is a shortcut, not the only path in.

  • Typing is first-class — the field parses forgivingly: "9:30 pm", "930", "14:00" all resolve to the same 24h value.
  • The list is for discovery — it surfaces the common stepped times so people don't have to type when a preset fits.
  • Keep the step sensible — a very small step makes a long, slow-to-scan list; let people type instead.
  • Bounds apply to both paths — min / max reject both out-of-range options and out-of-range typed entry.

Complete Do's and Don'ts

Guidelines for effective Time Picker usage.

Do
  • Match the step: Set step to the scheduling granularity (5, 15, 30, 60 min).
  • 24h for infra: Use hour-cycle="24" for logs, cron, and maintenance windows.
  • Bound the window: Give min / max for constrained windows (business hours).
  • Let people type: The list field parses "930", "9:30 pm", "14:00" — don't force the popover.
  • Store canonical: Keep the value as locale-independent 24h HH:mm; format only on display.
  • Announce selection: Read the chosen time via aria-live for screen readers.
Don't
  • Durations: Don't use it for "45 minutes" — that's a number field, not a time of day.
  • Hand-rolled AM/PM: Don't build a separate AM/PM toggle beside a text input — use hour-cycle.
  • Tiny step: Don't set a 1-minute step that makes an endless list — let users type.
  • Silent rejection: Don't drop an out-of-bounds typed time without surfacing an error.
  • Display strings: Don't store "2:30 PM" — the canonical value is always 24h HH:mm.
  • Leave list open: Don't keep the popover open after a selection — the user has moved on.

Accessibility

Guidelines for ensuring Time Picker is accessible across assistive technologies and input methods.

Keyboard Navigation

The list field is an editable combobox; the inline field is a row of spinbuttons.

VariantKeyAction
ListDown ArrowOpens the list popover.
Arrow Up / Arrow DownMoves the active option.
Home / EndJumps to the first / last option.
EnterSelects the active option.
EscCloses the list; returns focus to the field.
Direct typingType a time (9:30 pm, 930, 14:00) — parsed forgivingly.
InlineArrow Up / Arrow DownIncrements / decrements the active segment (with wrap).
Arrow Left / Arrow RightMoves between HH, MM, and AM/PM segments.
DigitsType into the active segment; auto-advances and clamps.
A / POn the AM/PM segment, sets AM / PM (or Up/Down toggles).

In the list variant, Tab closes the popover and moves focus on — the field is a combobox, not a modal, so focus is never trapped.

ARIA Attributes

  • List field: The editable input carries role="combobox" with aria-expanded, aria-controls, and aria-activedescendant.
  • Listbox: role="listbox" anchored to the field; each row is role="option" with aria-selected.
  • Inline segments: Each segment is role="spinbutton" with aria-valuemin / aria-valuemax / aria-valuenow / aria-valuetext.
  • Label association: The label is linked to the field; when label-position="none" the text is kept as aria-label.
  • Validation: Set aria-invalid="true" in Error state; link the helper via aria-describedby.
  • Now row: When show-now is set, expose the pinned row as a selectable option with an accessible name that includes the current time.

Screen Reader Guidance

  • Selection announcement: After the user picks or types a time, announce the formatted value (e.g. "2:30 PM selected") via aria-live.
  • Segment feedback: In the inline variant, aria-valuetext should read the human value ("30 minutes", "PM"), not the raw number.
  • Visual-only highlight: Never rely on colour alone — always pair the selected option with aria-selected.
  • Contrast: Selected-option text on the accent fill must meet WCAG AA 4.5:1. Out-of-bounds options use disabled text — verify against the list background.
  • RTL: Mirror the field layout and stepper column; the segment order (HH : MM) stays left-to-right as a numeric sequence.
  • Canonical value: The value is always 24-hour HH:mm — display formatting must not change what is stored or submitted.

Focus Management

  • On open (list): The active option is the current value, or the nearest in-bounds option when empty; focus stays on the field (combobox pattern).
  • On close (list): Focus stays on / returns to the field that owns the list.
  • Inline entry: Focus lands on the first segment; typing and arrows move it across segments without leaving the field.
  • No focus trap: The list is a non-modal combobox — Tab closes it and moves focus to the next control.
  • Visible focus indicator: The field shows a 2px accent ring; the active option shows a hover/active background. This must not be overridden.
  • Clicking outside: Dismisses the list and leaves the committed value untouched.
Focus ring spec
Focused field: 2px --uems-border-accent-focus ring. Active option: --uems-bg-primary-hover background.
