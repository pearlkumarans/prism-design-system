Overlay

A scrim/backdrop placed behind modals, dialogs, drawers, and popovers to obscure background content and trap focus. Always rendered as a full-viewport fixed layer. Pick the type that matches the surface: Dim for standard modals, Transparent for popover click-traps, Blur for premium frosted backdrops.

Anatomy

The overlay is a single rectangle with no child elements. In Figma each variant is drawn at 1440×900; in code it must always stretch to the full viewport (position: fixed; inset: 0).

1
2
1
Overlay (scrim)Single full-viewport layer. position: fixed; inset: 0; z-index below the dialog, above all page content. No children, no content.
2
Overlaid surfaceThe modal / drawer / popover the overlay backs. Owns focus trap, Escape handling, and its own z-index above the scrim.

When and Where to Use

Reach for an overlay whenever a layered surface needs the page behind it pushed back — visually, or just interactively. The surface decides the scrim; the user never interacts with the overlay as a thing in itself.

ScenarioType
Standard modal, dialog, or drawerDim
Dark-themed surface where a dark scrim has insufficient contrastLight
Popover, dropdown menu, or non-modal layer that needs outside-click dismissal without dimmingTransparent
Elevated/premium modal experience with frosted backgroundBlur
Frosted background with maximum content suppressionDim Blur

Behaviour

InteractionExpected handling
Click/tap on overlayDismiss the overlaid surface (modal, drawer, popover) — unless the dialog is blocking/required
EscapeDismiss the overlaid surface (handled by the surface, not the overlay)
ScrollLock body scroll while the overlay is visible (overflow: hidden on <body> or scroll-lock utility)
FocusThe overlay itself is never focusable; focus is trapped inside the overlaid surface
StackingOne overlay per layered surface; nested surfaces (modal → popover) each manage their own overlay/z-index

Do's and Don'ts

Do
  • Always use the theme tokens (--uems-bg-overlay, --uems-bg-quaternary-solid) rather than raw hex — the scrim must adapt across Dark/Night/Green theme modes.
  • Render exactly one overlay per modal layer; nested surfaces each manage their own overlay and z-index.
  • Lock body scroll while the overlay is visible, and release it on dismiss.
  • Give overlay-click dismissal keyboard parity — Escape must close the same surface.
Don't
  • Don’t stack dim overlays — stacked scrims compound opacity and over-darken the page.
  • Don’t rely on the scrim for text contrast — content on top of the overlay belongs to the dialog surface, not the overlay.
  • Don’t apply 70% via element opacity on the blur variants — it would also fade the backdrop-filter. Put the alpha on the background colour.
  • Don’t make the overlay focusable or give it a role — it is decorative, aria-hidden="true".

HTML structure

Rendered as a sibling immediately before the surface it backs. The component ships from design-system-library/src/components/overlay/ — load overlay.css and overlay.js (or the aggregate design-system-library/src/components/index.js).

<!-- Scrim + surface pair -->
<ds-overlay type="dim" open></ds-overlay>

<div role="dialog" aria-modal="true" class="modal">
  <!-- modal content -->
</div>

Attributes

AttributeValuesDefaultDescription
typedim | light | transparent | blur | dim-blurdimSelects the scrim treatment
openboolean—Overlay is visible while present. Also exposed as a JS property: overlay.open = true
staticboolean—Suppresses click-dismiss for blocking/required dialogs

Events

EventFired whenNotes
ds-dismissUser clicks the scrim (unless static)Bubbles + composed. The surface owns its state — listen and close there. Escape handling also belongs to the surface.

Wiring example

const overlay = document.querySelector('ds-overlay');
const dialog  = document.querySelector('.modal');

function openDialog()  { overlay.open = true;  dialog.hidden = false; }
function closeDialog() { overlay.open = false; dialog.hidden = true;  }

overlay.addEventListener('ds-dismiss', closeDialog);          // scrim click
document.addEventListener('keydown', (e) => {                 // keyboard parity
  if (e.key === 'Escape') closeDialog();
});

CSS notes

  • For Blur / Dim Blur, the 70% alpha sits on the background colour (rgba), not on opacity — element-level opacity would also fade the backdrop-filter effect.
  • A non-blurred fallback ships built-in: @supports not (backdrop-filter: blur(8px)) degrades Blur → Light and Dim Blur → Dim.
  • prefers-reduced-transparency is honoured the same way — blur variants swap to the solid styles.
  • Z-index comes from var(--z-overlay) (1300) — below the dialog surface, above all page content.

Accessibility

The overlay is decorative chrome — everything interactive lives on the surface above it. These minimums are non-negotiable.

ConcernGuidance
SemanticsThe overlay is decorative: aria-hidden="true", no role, not focusable (set automatically by <ds-overlay>)
ModalityPair with aria-modal="true" on the dialog and inert/aria-hidden background content
Focus trapFocus must remain within the overlaid surface while the overlay is visible
DismissalOverlay click dismissal must have keyboard parity (Escape)
Reduced transparency/motionHonour prefers-reduced-transparency by swapping Blur/Dim Blur to the solid Dim style (built into overlay.css)
ContrastThe scrim must not be relied on for text contrast — content on top of the overlay belongs to the dialog surface, not the overlay
