Item list

A stacked list of things that happened or need attention — activity feeds, approval queues, search results, release notes, execution steps. Each row is three regions: a leading rail, content, and an optional trailing action. This is not List: that one is a bulleted or numbered prose list. This one is a record list, with status, metadata, and an action per row. The timeline variant is the same row with the rail re-dressed as a dot and a connector.

Anatomy

Three regions, left to right: the leading rail carries status, the content carries the record, and the trailing control carries the one thing you can do about it.

Item list or List?

Two components with similar names and no shared anatomy. Pick by what a row is.

Item listList
A row is…A record — something that happened or needs attentionA point in prose — a feature, a step, a bullet
CarriesStatus, metadata, an actionA marker and text
Semanticsrole="list" over rendered rowsReal <ul>/<ol>
Reach for it whenThe list came from dataYou would have written a bullet list by hand

When and where to use

Reach for it whenever a panel lists records that came from data and each one may carry a single action.

Use it forReach for something else
Recent activity, audit trails, notification feedsRows you need to sort, page, or bulk-select → Data table
Approval and pending-action queuesField/value pairs on a detail page → Description list
Search results across modulesBulleted prose inside body copy → List
Release notes, what’s-new panelsA row that opens a whole page → make the title a link, not the row
Execution steps and progress logs (timeline)A branching or scheduled process → Stepper

The row is not a click target

This is the load-bearing decision in the component, and it is deliberate. The row hover exists to say “this action belongs to this row” — association, not affordance.

RuleWhy
No cursor: pointer on the rowA pointer on a non-clickable surface trains people to click and get nothing
No tabindex on the rowA focus stop that does nothing on Enter is worse than no focus stop
No selection model, no checkboxesBulk-select is Data table’s job; half a selection model is worse than none
Navigation goes on the title via hrefScreen readers and middle-click both get a real link
The trailing control is a real <a> or <button>Keyboard, focus ring, and context menu come for free
:focus-within lights the row tooA keyboard user tabbing to the action gets the same grouping a mouse user gets

When timeline stops being a variant

Timeline is a variant because the DOM is identical — it is a skin on the leading rail. Split it into its own component the day it needs any of these, because each one changes the anatomy rather than the skin.

RequirementWhat breaks
Timestamps on the opposite railBecomes a two-column axis; the row is no longer rail + content + trailing
Date-group headers between rowsNeeds a grouping layer the list does not have
Collapsible ranges (“12 more events”)Introduces row state and a disclosure control
A horizontal axisDifferent layout model entirely

    text:        '23 devices pending enrollment',
    description: 'Awaiting admin approval',
    icon:        'exclamation-circle',

    mono:        true,                // render output in the monospace stack

  },
];

Accessibility

The list announces as a list, the rail is silent, and the only focus stop in a row is the one thing that does something.

ConcernGuidance
Semanticsrole="list" on the container, role="listitem" on each row — screen readers announce list size and position
Leading railaria-hidden — the glyph restates what the text already says
StatusNever carried by colour alone; the glyph differs and the text or a badge states it
Trailing controlAuto-labelled with its subject — aria-label="Approve — 23 devices pending enrollment" — because “Approve” alone is meaningless in a screen reader’s list of controls
Focus orderOnly the title link and the trailing control are focusable. The row is not: a focus stop that does nothing on Enter is worse than no focus stop
Focus visibility:focus-within lights the whole row, so a keyboard user sees which record the focused action belongs to
Disabled rowsaria-disabled="true" plus pointer-events: none on the trailing region
MotionThe hover transition is dropped under prefers-reduced-motion
ContrastVerified in all six themes — light, dark, night, green-light, green-dark, green-night

Keyboard

KeyBehaviour
TabMoves to the next focusable control — a title link or a trailing action. Rows themselves are skipped.
EnterActivates the focused link or button.
SpaceActivates the focused button (native behaviour).

There is deliberately no arrow-key roving focus: the rows are not a menu, a listbox, or a grid, and giving them arrow navigation would promise a selection model that does not exist.
