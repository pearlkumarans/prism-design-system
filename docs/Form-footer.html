Form footer

The sticky action bar pinned to the bottom of a form or page — a left status/content area and a right-aligned button group (Save / Cancel / …). It spans the container width, sits on white with an upward elevation shadow (no border), and stays pinned while the form body scrolls. The buttons are the shared <ds-button>; the footer only owns the sticky bar + layout.

Layout & sizing

The bar is full-width; the left area fills the row and pushes the button group to the trailing edge (effective space-between). Height is a minimum, so it grows if content wraps.

When to use

  • The primary action bar for a form, settings page, wizard step, or fullscreen/modal editor — Save / Cancel and friends, pinned to the bottom.
  • When you need a persistent submit affordance while the form body scrolls.
  • To surface lightweight status alongside the actions (autosave time, unsaved-changes, selection count) in the left area.

When not to use

  • Dialog/modal actions that live inside the modal's own footer — use the modal's footer, not a page-level sticky bar.
  • A single inline button with no bar/elevation — just place a ds-button.

Sticky behavior

The footer is position: sticky; bottom: 0 — it pins to the bottom of its scroll container while the body scrolls beneath. Reserve bottom padding on the form body so the footer never overlaps the last field / a focused input.

RTL

The bar is a plain flex row — dir="rtl" mirrors it for free (status moves to the visual right, buttons to the left). No duplicate props; pass already-localized labels.

Basic usage

HTML
<ds-form-footer show-left dir="rtl">
  <span slot="left">Last saved 2 min ago</span>   <!-- or left-text="…" -->
  <ds-button slot="action" variant="tertiary">Reset</ds-button>
  <ds-button slot="action" variant="outline">Cancel</ds-button>
  <ds-button slot="action" variant="primary">Save</ds-button>
</ds-form-footer>

Attributes

AttributeValuesDefaultNotes
show-leftbooleantrueOn/off toggle for the whole left area (maps to Figma Show Left Slot). ="false" collapses it; buttons stay right-aligned.
left-texttext—Convenience status text for the left area when no slot="left" is provided.
livebooleanfalseSets aria-live="polite" on the left area — for status that updates (e.g. autosave time).
labeltextForm actionsAccessible name for the footer region (aria-label).
dir="rtl"—ltrMirrors layout; status text right-aligns.

Slots

SlotNotes
slot="left"The left area — status text, metadata, or any custom content. Omit to use left-text, or hide via show-left="false".
slot="action" (or default)The action buttons — pass the ds-buttons you need, in order (Primary trailing). Unmarked children are treated as actions too.

Events

The footer adds no events of its own — the slotted ds-buttons fire their own click. Wire your submit/cancel handlers on the buttons.

Roles & semantics

  • The bar is a role="group" with an aria-label (default "Form actions") — a labeled action region, not a landmark. Inside a <form>, keep it within the form.
  • Buttons are real ds-button (native <button>) with their own focus rings and disabled/loading states.
  • Live status text: set live so autosave/updates announce via aria-live="polite" without stealing focus.

Keyboard & focus

KeyAction
TabLeft status (if focusable) → button group left→right (Tertiary → Secondary → Primary). DOM order matches visual order in LTR and RTL.
Enter / SpaceActivates the focused button. Primary is the default submit.

Sticky, destructive & contrast

  • Reserve bottom padding on the form body so the sticky bar never overlaps a focused field.
  • Destructive actions (e.g. Delete) use variant="destructive", kept left-most and clearly labeled — separated from the Primary confirm to avoid mis-clicks; consider a confirmation step.
  • --uems-text-secondary status text on white passes AA.
