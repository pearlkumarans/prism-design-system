Progress Bar

A progress bar shows how far along a task is — uploading a file, running a scan, syncing a backup. Use the determinate mode when you know the percentage (5 of 12 files); use indeterminate when you only know that work is happening. Pair it with a short label so the user knows what’s progressing, not just that something is.

Content GuidelinesRecommended

Do
  • Use Large for prominent page-level progress; Small for dense lists or tables.
  • Keep the label concise (2–4 words: "Upload progress", "Storage used").
  • Show the % value alongside the bar so users can read the exact number.
  • Transition to Success variant at 100% completion.
Don't
  • Use Large inside a compact list item.
  • Write a full sentence as the label.
  • Rely on bar width alone for precision — perception is inaccurate.
  • Show 0% or a frozen bar while waiting — it implies the operation is stuck.

Icon Usage

Progress Bar itself has no icon slot, but it commonly pairs with status icons in the label or appears alongside step indicators. Use these pairings consistently.

Status icons in the label

Prefix the label with a 16px icon that matches the variant. The icon reinforces the meaning at a glance, especially in error states.

Step indicators (multi-step flows)

For multi-step wizards or onboarding, place small icon-filled circles before or above the bar segments. Use these icon states for each step:

Trailing action icons

For long-running operations, pair the Progress Bar with a trailing icon-button:

  • pause — allow user to pause an upload/download.
  • play — resume a paused operation (replaces pause icon).
  • close — cancel the operation. Always confirm before destructive cancel.
  • refresh — retry after a failure (only shown in Error variant).

Use 32px tap target with 16px icon. Place the action icon outside the bar's container so it doesn't compete visually with the fill.

When and Where to Use

Progress bars communicate measurable completion status across uploads, processing, and system operations.

When to use

  • To show measurable progress toward a known completion point (file upload, form completion, steps completed).
  • To communicate system status during a background operation (syncing, processing, building).
  • When the user benefits from knowing how much remains, not just that something is happening.
  • Use Indeterminate when the duration or percentage cannot be calculated.
  • Use Success / Warning / Error variants when the completion state carries a semantic outcome.

When NOT to use

  • Step-by-step workflows — use a Wizard instead. Progress bars don't communicate discrete steps clearly.
  • Circular loading — use Progress Loader for spinners inside buttons or inline loaders.
  • Binary complete / incomplete — use a Checkbox or a simple status indicator.
  • Page-level loading — use a top-of-page slim bar (e.g. NProgress pattern), not a full-width labelled progress bar.

Indeterminate Mode

When the total duration or steps of an operation are unknown, use variant="Indeterminate". The fill stub is a fixed-width segment (~33% of the track) that sweeps from left to right in a continuous animation.

  • Value label: Render "—" (em dash) or omit it entirely. Do not show "0%" — that implies 0% is known, which contradicts the indeterminate state.
  • Animation: Apply overflow: hidden on the Track element so the fill clips at the track boundaries.
  • Reduced motion: Respect prefers-reduced-motion — pause the animation and show a static 33% fill.

Complete Do's and Don'ts

Guidelines for effective progress bar usage.

Do
  • Use Large for prominent page-level progress; Small for dense lists or tables.
  • Keep the label concise (2–4 words: "Upload progress", "Storage used").
  • Show the % value alongside the bar so users can read the exact number.
  • Use Indeterminate when duration cannot be computed.
  • Transition to Success variant at 100% completion.
  • Set width: 100% in code so the bar fills its container.
  • Animate fill width with transition: width 300ms ease.
  • Respect prefers-reduced-motion — use instant updates instead of animations.
Don't
  • Use Large inside a compact list item.
  • Write a full sentence as the label.
  • Rely on bar width alone for precision — perception is inaccurate.
  • Show 0% or a frozen bar while waiting — it implies the operation is stuck.
  • Leave the bar in Default state after completion.
  • Reset to 0% on error without feedback.
  • Use Warning for purely in-progress states.
  • Hard-code the 280 px canvas width.
  • Force animations regardless of user preference.

Responsive fill (CSS)

/* Responsive fill */
.progress-bar {
  width: 100%;
}
.progress-bar__fill {
  width: calc(var(--progress-value, 0) * 1%);
  transition: width 300ms ease;
}

@media (prefers-reduced-motion: reduce) {
  .progress-bar__fill { transition: none; }
  .progress-bar--indeterminate .progress-bar__fill {
    animation: none;
    width: 33%;
  }
}

RTL Support

  • No RTL axis exists in the Figma component. Implement RTL by mirroring the fill direction in CSS: direction: rtl or transform: scaleX(-1) on the track.
  • The label row should also reverse: percentage left-aligned, label right-aligned in RTL contexts.

Accessibility

Guidelines for ensuring progress bar elements are accessible across assistive technologies.

ARIA Attributes & Screen Reader Guidance

ConcernRequirement
RoleUse role="progressbar" on the track element.
Value attributesSet aria-valuenow, aria-valuemin="0", aria-valuemax="100" dynamically.
IndeterminateOmit aria-valuenow when variant="Indeterminate" — its absence signals the value is unknown.
LabelProvide aria-label or aria-labelledby referencing the label text. e.g. aria-label="File upload progress".
Value textUse aria-valuetext when the visual label is non-numeric (e.g. "Step 3 of 8").
Disabled stateSet aria-disabled="true" on the container; visually greyed tokens already applied.

Live Region Announcements

  • aria-live="polite": Wrap in aria-live="polite" to announce progress changes to screen readers.
  • Throttle announcements: Avoid flooding the screen reader by throttling updates (e.g. announce every 10% or at key milestones).
  • Completion: Announce completion explicitly (e.g. "Upload complete") when reaching 100%.

Keyboard Interaction

Progress bars are read-only, non-interactive elements. They do not receive keyboard focus. The surrounding context (form, dialog, or page) conveys the progress information.

Motion Sensitivity

Indeterminate animation must pause when prefers-reduced-motion: reduce is set.

  • Reduced motion: When prefers-reduced-motion: reduce is active, disable the sweep animation and show a static 33% fill stub.
  • Determinate transitions: Also disable transition: width 300ms ease so the fill updates instantly.

RTL Considerations

  • No RTL axis exists in the Figma component. Implement RTL by mirroring the fill direction in CSS: direction: rtl or transform: scaleX(-1) on the track.
  • Ensure aria-valuenow and other ARIA attributes remain unchanged — screen readers handle directionality natively.
