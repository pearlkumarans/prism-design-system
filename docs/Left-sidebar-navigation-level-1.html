Sidebar Navigation Level 1

The Level 1 sidebar is how the user jumps between the major areas of a product — Dashboard, Endpoints, Patches, Reports. Each icon represents one area; clicking an icon opens its full menu in the Level 2 panel. Keep the list short (under 8 items) so the user can scan it without thinking.

Content GuidelinesRecommended

Do
  • Always set exactly one item to Active to reflect the current page.
  • Use the Add state only for primary creation actions (e.g. "Add Config").
  • Use Icon Only only as the collapsed state, toggled by the user.
  • Show tooltips on all items when in Icon Only mode.
  • Keep all items from the product's defined set — disable rather than hide items users shouldn't access.
Don't
  • Leave all items in Default — users need a clear location indicator.
  • Use Add state for regular navigation destinations.
  • Default to Icon Only — expanded labels aid discoverability.
  • Hide labels in collapsed mode without providing a hover tooltip.
  • Remove items from the nav list for items that are merely restricted — use Disabled state with a tooltip explaining why.

When and Where to Use

Guidelines for choosing when to use the Level 1 sidebar navigation.

When to use

  • As the primary navigation for any UEMS product module page.
  • Use Icon with Text by default to give all users clear navigation labels.
  • Switch to Icon Only when the user explicitly collapses the sidebar.
  • Only one item should be in Active state at a time — it reflects the current page.

When NOT to use

  • Do not use Level 1 navigation as a secondary/contextual navigation within a page — use a Tab Bar or Level 2 navigation instead.
  • Do not show more items than the product's defined set — use item visibility booleans to hide unused slots.
  • Do not place the Level 1 navigation horizontally — it is strictly a vertical sidebar component.

Choosing the Right Product Set

Always use the component set that matches the product context. Do not use the Configurations nav inside an MDM screen.

ScenarioHow to handle
Product has fewer than 6 itemsSet excess Item slots to OFF
Product needs 7–8 itemsSet Item 7 / Item 8 to ON
A nav item should not be accessibleSet State=Disabled via the Item Swap
Current page changesSet the matching item's Swap to State=Active

Complete Do's and Don'ts

Guidelines for effective sidebar navigation usage.

Do
  • Reflect current page: Always set exactly one item to Active to reflect the current page.
  • Add state purpose: Use the Add state only for primary creation actions (e.g. "Add Config").
  • User-driven collapse: Use Icon Only only as the collapsed state, toggled by the user.
  • Tooltips in collapsed: Show tooltips on all items when in Icon Only mode.
  • Preserve set items: Keep all items from the product's defined set — disable rather than hide items users shouldn't access.
Don't
  • Missing location: Leave all items in Default — users need a clear location indicator.
  • Misuse Add: Use Add state for regular navigation destinations.
  • Default collapsed: Default to Icon Only — expanded labels aid discoverability.
  • Missing tooltips: Hide labels in collapsed mode without providing a hover tooltip.
  • Remove restricted items: Remove items from the nav for items that are merely restricted — use Disabled state with a tooltip explaining why.

Collapse / Expand Toggle

The bottom of every navigation panel contains a collapse toggle (Bottom Item 2), visible in both Type variants.

  • In Icon with Text mode: renders full-width at 72px.
  • In Icon Only mode: renders at 44px, icon only.
  • On click: switches the parent sidebar between Icon with Text and Icon Only states.
  • The toggle itself does not change state — the consuming layout handles the type switch.

Collapse Toggle Pattern

const toggleBtn = document.querySelector('.nav-item--collapse');
const sidebar = document.getElementById('sidebar');

toggleBtn.addEventListener('click', () => {
  const isCollapsed = sidebar.classList.toggle('sidebar-nav--collapsed');
  toggleBtn.setAttribute('aria-expanded', String(!isCollapsed));
  toggleBtn.setAttribute('aria-label',
    isCollapsed ? 'Expand navigation' : 'Collapse navigation'
  );
});

Accessibility

Guidelines for ensuring Sidebar Navigation Level 1 is accessible across assistive technologies and input methods.

Keyboard Interaction

KeyAction
TabMove focus to the next nav item.
Shift+TabMove focus to the previous nav item.
Enter / SpaceActivate the focused nav item.
HomeMove focus to the first nav item.
EndMove focus to the last nav item.
Enter on collapse toggleToggle between Icon with Text and Icon Only.

ARIA Attributes & Screen Reader Guidance

  • Landmark: Wrap in <nav> with aria-label="Main navigation".
  • Current page: Set aria-current="page" on the active item's <a> tag.
  • Icon Only mode: Add aria-label to each nav item containing the full item name. Provide visible tooltip on hover/focus.
  • Disabled items: Set aria-disabled="true" and tabindex="-1". Include a tooltip explaining unavailability.
  • Collapse toggle: Use aria-expanded (true/false) and aria-controls pointing to the sidebar container.
  • Icons: Mark icon SVGs aria-hidden="true" — labels carry the semantic meaning.
  • Add item: The "Add" state button should be a <button> element (not <a>), as it opens a creation dialog rather than navigating to a page.

Focus State Design

  • Focus ring: Do not remove the default focus outline — use :focus-visible to style a custom 2px ring matching Border-Accent (#006AFF).
  • Full keyboard navigation: Full keyboard navigation via Tab/Shift+Tab; Enter/Space to activate; Home/End to jump to first/last item.
Focus ring: 2px border + 3px shadow
Border: #006AFF | Shadow: rgba(0,106,255,0.20)

RTL Support

  • Direction: Set dir="rtl" on the <nav> element for Arabic/Hebrew layouts; icon wrap and label stack direction invert automatically.
  • Border position: The right border flips to the left side in RTL mode.
  • Collapse icon: The collapse chevron direction should mirror to point towards the sidebar edge.
