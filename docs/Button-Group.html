Button Group

A group of value-bearing buttons — a segmented picker, a multi-select toggle grid (months, weekdays), or an action toolbar. One primitive, three selection modes, each wired to the correct WAI–ARIA pattern. Reach for it when you have a compact set (~2–12) of short options meant to be seen at once.

Anatomy

A group container holds a row/grid of item buttons; the selected item(s) fill with the accent. One label names the whole group.

1
Group containerrole="radiogroup" (single) or group (multi / none), with an accessible label.
2
ItemA <button>; optional leading icon + label. Icon-only needs an ariaLabel.
3
Selected itemFilled accent + aria-checked (single) / aria-pressed (multi).
4
Roving focusOne Tab stop; arrow keys move focus (and select, in single mode) between items.

Selection modes

Selection is the axis. Interact with any group — toggle, tab in, arrow-key around.

single  exclusive — segmented control
multi  months (grid, columns=6)
multi  weekdays (grid, columns=7)
none  action toolbar — icon-only
multi  select all / deselect all — show-select-all

When to use

Only where the alternatives don’t fit.

If you need…UseNot this because…
Pick one/many from a compact set of buttons (months, weekdays, ordinals, view switch)ds-button-group—
Switch between views / panelsds-tab-bar-*Navigation, not a value
One choice from a vertical form list with descriptionsds-radio-groupLong labels + helper text; not compact
Many choices from a vertical form listds-checkbox-groupList layout, not a chip grid
Choose one value from a long listds-input-selectOverflows to a menu; groups are for short sets
A single on/offds-toggleBinary, one control

Variants

separated = bordered chips with a gap. attached = no gap; items collapse into a connected control with hairline 1px seams and rounded outer corners — works for a single row and a multi-row grid.

attached

Sizes

Small · Medium (default) · Large — padding + font from size tokens.

Layouts

Row (wraps) · grid (fixed columns) · column. The group hugs its content by default; equal equalises items, and full-width stretches to the container (implying equal on a row).

Default · hover · selected · focus (Tab in and arrow) · disabled item · disabled group.

Do & Don’t

Do

  • Give icon-only items an ariaLabel.
  • Use single for mutually-exclusive picks; multi for independent toggles.
  • Keep labels short (1–2 words) so items stay compact.
  • Use attached for a tight segmented control, separated for a chip grid.
  • Keep to ~2–12 options meant to be seen at once.

Don’t

  • Use it for view navigation — that’s ds-tab-bar-*.
  • Use it for a long option list — that’s ds-input-select.
  • Hand-roll aria-pressed button grids — this owns state, keyboard & ARIA.
  • Rely on colour alone to signal selection.
  • Mix wildly different label lengths in one attached group.

Content guidelines

  • Write items as values, not actions — “List / Grid”, not “Show list”. (Action mode is the exception.)
  • Order items logically: chronological (Jan…Dec), by magnitude (Low…Critical), or by frequency of use.
  • Prefer text labels; use icon-only in dense toolbars where the glyph is unambiguous (B / I / U).

Examples

          
Multi (property-driven) — the months case:

          
<ds-button-group id="repeat" selection-mode="multi" layout="grid" columns="6" label="Repeat"></ds-button-group>

repeat.items  = MONTHS.map(m => ({ value: m, label: m }));
repeat.values = ['Jan', 'Feb', 'Apr'];
repeat.addEventListener('ds-button-group-change', e => save(e.detail.values));

          
Single (segmented) — a view switcher:

          
<ds-button-group selection-mode="single" variant="attached" value="list" label="View"></ds-button-group>

view.items = [{ value:'list', label:'List' }, { value:'grid', label:'Grid' }];
view.addEventListener('ds-button-group-change', e => setView(e.detail.value));

          
Action toolbar (none) — icon-only:

          
<ds-button-group selection-mode="none" variant="attached" label="Format"></ds-button-group>

fmt.items = [{ value:'bold', icon:'bold', ariaLabel:'Bold' }, /* … */];
fmt.addEventListener('ds-button-group-item-click', e => exec(e.detail.value));

Keyboard

          

            

              
KeyAction

              
                
TabMove into / out of the group (one stop — roving tabindex).

                
← →Move within the row (RTL flips). In single mode also selects.

                
↑ ↓Grid: move to the row above/below (by columns). Row/column: previous/next.

                
Home / EndFirst / last enabled item.

                
Space / EnterToggle (multi) / select (single) / activate (none) the focused item.

              
            

          


          
Focus & behaviour

          
    
            
  • Roving tabindex — exactly one item is tabbable; focus stays in sync with mouse / SR / programmatic focus.
    • 
            
  • Disabled items are skipped by keyboard nav and excluded from value / values.
    • 
            
  • State is carried by fill and text colour, never colour alone; a visible focus ring is always shown.
    • 
            
  • Icon-only items must set ariaLabel for a screen-reader name.
    • 
            
  • Transitions are gated on prefers-reduced-motion.
