Tab Filter

A tab filter slices the same data set by one short axis — All / Open / Closed, Day / Week / Month, List / Grid. One option is always selected, so the user sees the data immediately update as they switch. Use it for 2–7 mutually exclusive choices that the user wants to flip between quickly; for longer lists or multi-select, reach for a Dropdown or Checkbox group.

Variants

Tab Filter has a single visual style but applies to four common usage patterns. Pick the right one based on what the filter affects.

Pattern When to use Typical options Badge?
Status filter Filter a single dataset by lifecycle state. Most common pattern. All · Open · Closed · Archived Yes — show count
View switcher Toggle between presentations of the same data (List vs Grid, Calendar vs Timeline). List · Grid · Calendar No — use icons
Time range Re-scope a report or chart to a different window. Day · Week · Month · Year No
Category filter Limit to a small enumerable set (≤7) of categories. All · Apps · Devices · Users Optional

Rule of thumb: if the change re-queries the same data → Tab Filter. If it loads peer-level content → Tab Bar Horizontal.

Content GuidelinesRecommended

Do
  • Always have one option selected — default to a sensible "All" when applicable.
  • Keep labels parallel — same part of speech, similar length.
  • Use the smallest count variant that fits your options.
  • Show the result immediately on selection change — no Apply button.
  • Reflect the selected filter in the URL so deep links work.
  • Use a numeric badge for result size when it adds value (Open · 12).
  • On mobile (< 600px), allow horizontal scroll on the track instead of wrapping options.
  • Persist the last selection in localStorage for view-switcher patterns.
Don't
  • Render Tab Filter with no active option.
  • Mix nouns and verbs (e.g. "Open / Resolve / All").
  • Use Tab Filter for > 7 options or long phrase labels.
  • Use a textual badge (Open · New!) — the slot is for counts.
  • Defer filtering behind a confirmation — the white-card metaphor promises "this is your current view".
  • Use Tab Filter for switching between destinations — reach for Tab Bar Horizontal.
  • Wrap options to two rows on small screens — collapse to a Single Select dropdown instead.
  • Stack two Tab Filters in the same row — use only one filter dimension per view.

Properties

el.options = [
  { value: 'all',    label: 'All',    badge: 42 },
  { value: 'open',   label: 'Open',   badge: 12 },
  { value: 'closed', label: 'Closed', badge: 30 },
];
el.value = 'open';

// Per-option fields:
// { value, label, labelRtl?, icon?, badge?, disabled? }

Event

Listens to keyboard arrows + clicks. Fires on every selection change.

el.addEventListener('ds-tab-filter-change', (e) => {
  console.log(e.detail.value);   // 'open'
  console.log(e.detail.option);  // { value, label, … }
});

Accessibility

Roles & ARIA

ConcernImplementation
Wrapper rolerole="radiogroup" with an accessible name via aria-label.
Option roleEach option is role="radio" with aria-checked.
Focus orderSingle tab stop. Inside the group, ← / → move the selection (roving tabindex).

Keyboard

KeyBehavior
TabMoves focus into / out of the filter as a single stop, landing on the active option.
← / →Moves selection between options. Selection commits on each move — this is a filter, not a tab.
Home / EndJumps to first / last option.
Enter / SpaceRe-commits the focused option (no-op if already selected).

Indicator

Selection is conveyed by two channels — surface (white card) and weight (medium vs regular). Never rely on colour alone.
