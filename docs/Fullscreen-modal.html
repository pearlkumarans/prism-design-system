Fullscreen Modal

A fullscreen modal takes over the viewport for a focused, self-contained flow — a multi-step wizard, an enrolment journey, an embedded preview. Use it when the task needs the whole screen but the user shouldn’t lose their place behind it. A 40 px band of the page peeks at the top so the user remembers this is a layer they can close, not a navigation jump.

Content GuidelinesRecommended

Do
  • Lead the title with what the modal is for: "Configure SAML SSO", "Import contacts".
  • Keep the description to one short line summarising what the user can do here.
  • Place dismissive actions (Cancel, Back) on the left of the action group; primary on the right.
  • Use the left footer slot for utility — TextLink to docs, "Don't show again" checkbox, save status.
  • Make the body the sole scroll container; header and footer stay pinned.
  • Disable backdrop dismiss when there are unsaved changes; warn before closing.
Don't
  • Use generic titles like "Settings".
  • Repeat the title in the description or use it for marketing language.
  • Scatter actions across the left and right footer slots.
  • Let the entire dialog scroll — the footer must always be visible.
  • Allow accidental dismissal of in-flight wizard state.
  • Use a danger-toned leading icon — reach for Confirmation Modal for destructive surfaces.

RTL (Right-to-Left)

For Arabic, Hebrew, and other RTL locales, the header close button moves to the leading edge, the leading icon flips to the right of the title, and footer action ordering reverses so the primary stays on the visual leading edge.

LTR (default)
  • Close button: right
  • Leading icon: left of title
  • Primary action: right footer
  • Cancel / Back: left of primary
RTL
  • Close button: left
  • Leading icon: right of title
  • Primary action: left footer
  • Cancel / Back: right of primary

How it works: set dir="rtl" on the modal or any ancestor. The component reads ambient direction via :dir(rtl) selectors in fullscreen-modal.css and flips header layout, icon padding, and footer flex direction automatically. Try it in the playground — the "Open as full overlay" button respects the page's dir attribute.

Usage

When to reach for a Fullscreen Modal versus alternative dialog patterns.

When to use

  • Multi-step flows that need their own focused canvas: onboarding, wizards, structured imports.
  • Rich editing experiences that won't fit in a centered modal — entity detail panels, JSON editors, image cropping.
  • Mobile-first or responsive layouts — the same component fills a phone screen naturally.
  • Patterns that would otherwise need a new page but should preserve the user's place in the host app.

When not to use

SituationUse instead
Binary confirmation (Delete / Cancel)Modal / Confirmation
Short form (3–5 fields)Standard centered Modal
Persistent contextual panel beside the canvasDrawer / Side Sheet
Content that should live at its own URLA real page
Onboarding overlays pointing at UICoachmark / Tour

Keyboard & focus

  • Esc dismisses (suppress only when there are unsaved changes).
  • Tab / Shift+Tab cycle inside the dialog only — focus is trapped while open.
  • On open, focus moves to the first focusable control inside the body.
  • On close, focus returns to the originating trigger element.
  • Body region scrolls independently; document scroll is locked while open.
