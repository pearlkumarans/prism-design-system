Avatar

An avatar puts a face to a name — the user’s photo when they’ve set one, their initials when they haven’t, a generic icon as a last resort. Use it anywhere a person needs to be quickly recognisable: comment threads, member lists, mention pickers, the user menu in the header. Stack avatars with a “+3” counter when more people are involved than fit.

Content GuidelinesRecommended

Do
  • Always provide accessible text alternative (alt or aria-label).
  • Use Image type when profile photo is available.
  • Fall back gracefully: Image → Initials → Placeholder Icon.
  • Use consistent avatar sizes within same context.
Don't
  • Don't use Hover type as default or in read-only views.
  • Don't use initials with more than 2 characters.
  • Don't stretch or deform images.
  • Don't use avatars as sole identification in critical contexts.

Icon Usage

The Avatar surface displays one of three content types — image, initials, or a placeholder icon. Pick the right type based on what's available and the context.

Content typeWhen to useFallback behavior
ImageUser has uploaded a profile photo. Default for authenticated users.If image fails to load, fall back to Initials.
InitialsNo profile photo available. Use 1–2 characters from the user's name (first letter of first + last name).If no name available, fall back to Placeholder Icon.
Placeholder iconUnauthenticated/anonymous user, system entity, or completely unknown identity.Final fallback — use the user icon by default.

Icon sizing inside avatar

The placeholder icon scales to ~50% of the avatar diameter so it sits comfortably inside the circle with visual breathing room. The component handles this automatically — do not override icon size manually.

Status / presence icons (overlay)

For optional status overlays in the bottom-right corner, use a small ds-status-indicator dot rather than a full icon. Reserve icon overlays for action affordances (camera for upload, edit-pencil for editable avatars). Cap overlay diameter at ~30% of the avatar diameter.

RTL (Right-to-Left)

The Avatar is a circular surface containing either an image, initials, or a placeholder icon — all of which are visually symmetric. It looks identical in LTR and RTL contexts and is fully RTL-safe.

  • Initials: use the localized initial characters for the user's name (e.g., Arabic letters for an Arabic name). The component centers any 1–2 character string regardless of script.
  • Status dot: the optional presence indicator sits at the bottom-right corner in LTR and bottom-left in RTL — positioned via inset-inline-end so it flips automatically.
  • In a row of avatars (stacked): stacking order is controlled by the parent container's flex-direction. In RTL contexts the leading edge naturally becomes the right, with avatars stacking left-to-right visually.

When and Where to Use

Avatars visually represent users and entities across the interface, providing quick identification in lists, headers, and interactive contexts.

When to use

  • Navigation headers for logged-in user identification.
  • User lists and team member displays.
  • Comment threads and activity feeds.
  • Profile pages and user detail panels.

When NOT to use

  • As decorative elements without user association.
  • As buttons or action triggers (except Hover type for photo upload).
  • For non-person entities where a logo or icon is more appropriate.
  • In contexts where the user's full name is sufficient.

Complete Do's and Don'ts

Visual and interaction guidelines to ensure avatars are effective, consistent, and accessible.

Do
  • Provide alt text: Always include alt or aria-label with the user's full name for image avatars.
  • Use fallback chain: Attempt Image first, then Initials, then Placeholder Icon for graceful degradation.
  • Keep sizes consistent: Use the same avatar size within lists, tables, and repeated UI contexts.
  • Pair with name: In most contexts, display the user's name alongside the avatar for clarity.
Don't
  • No long initials: Don't use more than 2 characters for initials.
  • No deformed images: Don't stretch, squish, or crop images in non-uniform ways.
  • No misused Hover type: Don't show the Hover overlay in read-only or non-editable contexts.
  • No sole identification: Don't use avatars as the only way to identify users in critical workflows.

Accessibility

        
Guidelines for ensuring all avatar interactions are accessible across assistive technologies.


        

        

          
Accessibility Guidelines

          

            
RequirementImplementation

            
              

                Alt Text
                Use alt="[User's full name]" for image avatars so screen readers announce the person's identity.
              

              

                Decorative Avatars
                When avatar appears alongside a visible name, use alt="" or aria-hidden="true" to avoid redundant announcements.
              

              

                Disabled State
                Apply aria-disabled="true" to communicate the disabled state to assistive technologies.
              

              

                Hover / Editable
                Must be keyboard accessible. Use aria-label="Change profile photo" and ensure the overlay trigger is focusable.
              

              

                Color Contrast
                WCAG 2.1 AA (4.5:1) for initials text on tinted backgrounds. #0E2553 on #EAF0FC passes at 8.2:1.
              

              

                Focus
                Visible focus ring on editable avatars using Border-Accent-Focus token (#006AFF), 2px solid with 2px offset.
