Drawer

The Drawer is a side sheet — header, scrollable body, and footer — that slides in from the left or right edge over an optional scrim. Use it for detail views, forms, and focused tasks that benefit from extra width without leaving the page. It comes in four sizes (S 320 / M 480 / L 640 / Full) and supports a rich footer: a leading text link plus a right-aligned button group. Modal by default (scrim, focus trap, Esc, scroll-lock); set modal="false" for a non-blocking panel.

Content GuidelinesRecommended

Do
  • Anchor to the right for detail views and forms; reserve the left edge for navigation.
  • Use a modal drawer for tasks that must be resolved or dismissed before continuing.
  • Pick the size by content density — S for compact panels, L for dense forms or tables.
  • Pin the header and footer; let only the body scroll.
  • Name the primary footer button for its action ("Save", "Apply") — not "OK".
  • Return focus to the trigger when the drawer closes.
Don't
  • Stack drawers or open a drawer from within a drawer — route to a new step instead.
  • Put primary navigation in a modal drawer on desktop — use a Right pane.
  • Hardcode the panel width or scrim color — use size and the tokens.
  • Let the whole panel scroll — keep actions reachable in the pinned footer.
  • Hide the close affordance without giving another clear way out.
  • Enable overlay-click dismissal for forms with unsaved input.

Usage

When to reach for the Drawer versus its panel siblings.

When to use

  • A detail view or form that benefits from extra width while keeping the page context behind it.
  • A focused task the user should resolve or dismiss before continuing — use a modal drawer.
  • Contextual settings, filters, or a record preview that opens from a list or table row.
  • A multi-step flow within one surface — use show-back and the ds-drawer-back event.

When not to use

  • A short, centered yes/no decision — use Confirmation Modal.
  • A centered, content-first dialog — use Modal.
  • Persistent desktop utilities or navigation alongside the page — use Right pane.
  • A non-blocking acknowledgement — use Toast or Inline message.

Do & Don't

Do
  • Anchor to the right for detail views and forms.
  • Use a modal drawer for tasks that must be resolved before continuing.
  • Pin the header and footer and scroll only the body.
  • Return focus to the trigger when the drawer closes.
Don't
  • Stack drawers or open a drawer inside a drawer.
  • Put primary navigation in a modal drawer on desktop — use a Right pane.
  • Hardcode the panel width or scrim color — use size and tokens.

Install & usage

Register the component, then drive it with attributes and slots. Source: design-system-library/src/components/drawer/drawer.js.

Register the component

JS
<script type="module" src="design-system-library/src/components/drawer/drawer.js"></script>

Basic markup

HTML
<ds-drawer id="details" title="Drawer title" subtitle="Supporting text">
  <div slot="body">Body content goes here.</div>
  <ds-text-link slot="footer-start" href="#">Learn more</ds-text-link>
  <ds-button slot="footer" variant="outline" size="small">Cancel</ds-button>
  <ds-button slot="footer" variant="primary" size="small">Save</ds-button>
</ds-drawer>

<ds-button id="open" variant="primary">Open drawer</ds-button>
<script>
  open.addEventListener('click', () => details.open());
</script>

All attributes

HTML
<ds-drawer
  side="right"            <!-- left | right -->
  size="m"               <!-- s | m | l | full -->
  title="Drawer title"
  subtitle="Supporting text"
  show-header="true"
  show-footer="true"
  show-back="false"
  show-close="true"
  modal="true"
  dismiss-on-overlay="true"
  footer-align="default"  <!-- default | centered -->
  rtl
  open>
</ds-drawer>

Events & methods

JS
const drawer = document.querySelector('#details');

// Methods
drawer.open();
drawer.close();

// Restore focus to a specific element on close
drawer.returnFocusTo = document.querySelector('#trigger');

// Events
drawer.addEventListener('ds-drawer-open', () => {});
drawer.addEventListener('ds-drawer-close', (e) => {
  console.log(e.detail.reason); // 'esc' | 'overlay' | 'close'
});
drawer.addEventListener('ds-drawer-back', () => {});

Accessibility

Guidelines for an accessible Drawer across assistive tech and input methods.

Roles & ARIA

ConcernImplementation
Rolerole="dialog" on the panel, with aria-modal="true" when modal (and "false" for non-modal).
Titlearia-labelledby points to the title element.
Bodyaria-describedby points to the body region.
Close buttonaria-label="Close".
Back buttonaria-label="Back".

Keyboard & focus

Key / actionBehavior
EscDismiss the drawer (emits ds-drawer-close with reason esc).
Tab / Shift+TabCycles focus inside the panel only — focus is trapped while a modal drawer is open.
Click on scrimDismiss only when dismiss-on-overlay is on (default) and the drawer is modal.
  • On open, focus moves to the first focusable element inside the panel (or the panel itself).
  • On close, focus returns to the triggering element (or returnFocusTo if set).

Other concerns

ConcernRequirement
Body scroll-lockModal drawers lock body scroll while open and restore it on close; non-modal drawers do not.
Color contrastTitle --uems-text-primary and subtitle / body --uems-text-secondary on the panel surface meet WCAG 2.1 AA.
Motionprefers-reduced-motion: reduce replaces the slide + fade with instant show / hide.
RTLrtl (or host dir="rtl") mirrors the header order and text alignment of the title, subtitle, and body.
Tall contentThe body scrolls; the header and footer stay pinned so actions are always reachable.
