Filter Panel

A schema-driven side panel that collects filter criteria for a data surface (table, list, cards) and emits a structured value. It owns layout, collapsible groups, active-filter chips, clear-all, and an optional Apply footer, and delegates each field to an existing Prism input. Pair it with a Data table; for one-off inline inputs use the form fields directly.

Anatomy

Header (title + result count) · active-filter chips + Clear all · a scrollable body of collapsible groups, each delegating to a Prism input · an optional Apply footer (apply mode).

Emitted value (live)

{}

Presentation modes

Docked

In-flow sticky column beside the content — the default. Ideal next to a data table.

Drawer

Off-canvas end-docked sheet with a scrim. Esc / backdrop close. Good for narrow / mobile.

Popover

Anchored flyout from a “Filter” button. Light-dismiss (outside click / Esc).

Responsive

collapse-at="<px>" auto-presents a docked panel as a drawer below that container width.

When to use

  • Use it whenever a collection > ~10 items needs categorical, range, or keyword filtering.
  • Prefer docked beside a table; switch to drawer on narrow layouts (or set collapse-at).
  • Use live mode for client-side tables (instant), apply mode for server queries (batch on Apply).
  • Let the panel own the active-filter chips — don’t duplicate them in the content area.

Pairing with a data table

The table’s toolbar filter icon toggles the panel; the panel’s change / apply event feeds table.rows. Reference: Layout/views/layout-list-view.html.

panel.addEventListener('ds-filter-panel-change', e => {
  table.rows = query(e.detail.value);   // host owns the query
});

Usage

<ds-filter-panel id="fp" title="Filters" result-count="24 results"></ds-filter-panel>
<script type="module">
  fp.groups = [
    { id:'platform', label:'Platform', type:'checkbox', options:[
      { label:'Windows', value:'win', count:28 }, { label:'macOS', value:'mac', count:12 } ] },
    { id:'status', label:'Status', type:'radio', options:[
      { label:'Managed', value:'managed' }, { label:'Pending', value:'pending' } ] },
    { id:'owner', label:'Owner', type:'select', multi:true, options:[ /* … */ ] },
    { id:'risk', label:'Risk Score', type:'range', min:0, max:100 },
  ];
  fp.value = { platform:['win'] };
  fp.addEventListener('ds-filter-panel-change', e => render(e.detail.value));
</script>

Group schema

type FilterGroup = {
  id: string; label: string;
  type: 'checkbox'|'radio'|'select'|'search'|'range'|'toggle'|'date'|'daterange'|'tags'|'custom';
  options?: { label, value, count?, disabled? }[];
  multi?: boolean; placeholder?: string;
  min?, max?, step?;          // range
  toggleLabel?: string;       // toggle
  maxVisible?: number;        // checkbox "+N more" cap (default 8)
  render?, sync?, chipLabel?; // custom
};

Accessibility

  • Root is a labeled complementary region; each group is a labeled section with a collapsible <button> header exposing aria-expanded.
  • Active-filter chips are removable controls labeled by the option; removing one re-syncs the underlying field.
  • Fields inherit the keyboard + ARIA behavior of the underlying Prism inputs (arrow keys in radio/checkbox groups, listbox semantics for select).
  • Drawer / popover set role="dialog" / aria-modal, move focus in on open and return it to the trigger on close, and dismiss on Esc (+ backdrop / outside click).
  • Design tokens only; works across all themes and RTL. All DOM queries are scoped to the component root.
