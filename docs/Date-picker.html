Date Picker

A date picker is the field where the user lands when they need to set a date — they can type it in DD/MM/YYYY for speed, or click the calendar icon to open a picker. Use date ranges (with two thumbs) for filters and report periods; offer preset shortcuts (Today, Yesterday, Last 7 days) so users with a common need don’t have to click through the calendar.

Anatomy

The date picker input is composed of three numbered regions. Each label is anchored to the live preview with a connector line.

Content GuidelinesRecommended

Do
  • Use type="range" when start and end dates are both required.
  • Surface common spans as presets (Today, Last 7 / 30 days, This month).
  • Enable showFooter when the picker drives an expensive operation.
  • Respect minDate / maxDate — disable invalid days in the grid.
  • Announce the selected date via aria-live on selection.
  • Close the popover after Apply (or after single-click selection when no Footer).
Don't
  • Use two independent Single pickers for a date range — they can't enforce end ≥ start.
  • Hide presets behind "Custom" when ≥ 60% of users pick one of them.
  • Enable Footer for inline form fields where immediate commit is expected.
  • Let users pick an invalid date and only reject it on form submit.
  • Flip only the input without mirroring the calendar grid in RTL.
  • Hard-code one date format globally — keep it locale-aware.

Presets panel icons

When showing the side panel with preset ranges (Today, Last 7 days, etc.), keep the preset list mostly text-based. Icons are optional and should only be used for spatial/semantic clarity:

  • circle-dot — "Today" preset (matches the current-day indicator inside the grid).
  • arrow-left — "Last N days" presets (looking backward in time).
  • arrow-right — "Next N days" presets (looking forward).
  • calendar-range — "Custom range" preset that opens a free-form range selector.

Footer action icons

When showFooter is enabled, the footer has Cancel and Apply buttons. These are text-only by convention — do not add icons. The only exception is when space is extremely constrained:

  • check + "Apply" — icon-button variant for mobile/compact layouts.
  • close + "Cancel" — matches the check pattern in compact mode.

Rule of thumb: calendar/clock icons identify the picker. Inside the popover, chevrons are the only critical icons — everything else should be text. Avoid icon-only buttons in this surface; the popover is the user's chance to read a label, so use that affordance.

When and Where to Use

Date Picker is designed for calendar date selection via a text input and popover.

When to use

  • When users must select a specific calendar date (date of birth, due date, appointment).
  • When users must select a span of dates (report range, booking, date filter) → use type="range".
  • When presets (Today, Last 7 days, This month) cover the majority of cases → enable showPresets.
  • When the selection must be confirmed before applying (filters, batch ops) → enable showFooter.

When NOT to use

  • For single-day recurring selection (day-of-week) — use Checkbox Group or Radio Group.
  • For date + time input — use a DateTime Picker (Date Picker + time input).
  • For free-form text dates in prose — use a plain Text Input.
  • For scheduling multiple discrete dates — use a multi-date calendar pattern.

Single vs Range

Pick the Type axis based on the selection model required.

TypeBehaviourWhen to pick
singleOne input, one calendar. Selecting a day commits immediately (or stages if showFooter).DOB, appointment, due date, scheduling.
rangeTwo inputs (start, end) + dual calendar. First click = start; second click = end. Days between render a range highlight.Report period, booking, filtering records between dates.

Presets vs Manual Entry

Presets short-circuit common date spans. Keep manual entry available for everything else.

  • Surface presets when ≥ 60% of users pick one of them (Today, Last 7 days, This month). They reduce clicks to one.
  • Always keep manual day-grid selection available — presets are shortcuts, not replacements.
  • Keep presets concise — a long list clutters the popover and increases scan time.
  • Allow custom presets via the presets prop (e.g. "This quarter", "Year to date") when the domain calls for it.

Complete Do's and Don'ts

Guidelines for effective Date Picker usage.

Do
  • Range for spans: Use type="range" when start and end dates are both required.
  • Surface presets: Offer Today, Last 7 / 30 days, This month for common spans.
  • Staged commit: Enable showFooter for expensive operations (report, query).
  • Respect bounds: Disable invalid days in the grid — don't error only on apply.
  • Mirror for RTL: Mirror the weekday row and grid order, not just the input.
  • Locale-aware format: DD/MM/YYYY for APAC/EU, MM/DD/YYYY for en-US.
  • Close after commit: Close the popover after Apply (or after single-click select without Footer).
  • Announce selection: Read the selected date via aria-live for screen readers.
Don't
  • Two Single pickers: Don't use two independent Single pickers for a range — they can't enforce end ≥ start.
  • Hide frequent presets: Don't tuck popular presets behind "Custom" when most users need them.
  • Footer on inline forms: Don't gate immediate-commit form fields behind an Apply button.
  • Errors only on submit: Don't let users pick an invalid date and reject it only at form time.
  • Half-RTL: Don't flip only the input without mirroring the calendar grid.
  • Hard-coded format: Don't force one format globally — respect locale.
  • Leave popover open: Don't keep the popover open after Apply — the user has moved on.
  • Visual-only highlight: Don't rely on visual selection alone — non-sighted users won't know.

Accessibility

Guidelines for ensuring Date Picker is accessible across assistive technologies and input methods.

Keyboard Navigation

The input accepts direct typing; the popover grid supports full arrow-key navigation.

TargetKeyAction
InputDown Arrow / SpaceOpens the calendar popover.
EscCloses the popover; returns focus to the input.
Direct typingType in DD/MM/YYYY format (locale-aware).
Day gridArrow Left / Arrow RightMoves focus ±1 day.
Arrow Up / Arrow DownMoves focus ±1 week.
PageUp / PageDownMoves focus ±1 month.
Shift+PageUp / Shift+PageDownMoves focus ±1 year.
Home / EndJumps to the start / end of the week.
Enter / SpaceSelects the focused day.
EscCloses the popover without committing.

The popover must trap focus within itself while open. Tab cycles through: grid → presets → footer buttons → back to the grid.

ARIA Attributes

  • Input element: Native <input type="text"> with pattern mask, or <input type="date"> as a progressive-enhancement baseline.
  • Popover: role="dialog" aria-modal="false" anchored to the input.
  • Label association: Connect <label for="id"> to the input. For Range, wrap in a <fieldset> + <legend> with Start / End labelled inputs.
  • Calendar grid semantics: role="grid" on the day grid, role="row" on each week, role="gridcell" on each day, role="columnheader" on weekday abbreviations.
  • Current day: Mark today with aria-current="date".
  • Selected state: Set aria-selected="true" on selected day cells. For Range, also on days between endpoints.
  • Validation: Set aria-invalid="true" in Error state; link the helper via aria-describedby.
  • Range completion: When the user has a start but no end, set aria-describedby to say "End date required".

Screen Reader Guidance

  • Month navigation announcement: On month change, announce the new month/year via aria-live="polite" on a hidden status node.
  • Selection announcement: After the user picks a day, announce the fully-formatted date (e.g. "15 March 2026 selected") via aria-live.
  • Visual-only highlight: Never rely on colour alone — always pair with aria-selected and live announcements.
  • Contrast: Selected-day text on BG-Accent must meet WCAG AA 4.5:1. Outside-month days use Text-Disabled — verify against grid background.
  • RTL: Mirror the weekday-row order, chevron direction, and Range input order (end on the left, start on the right).
  • Time zones: Always store UTC internally; format on display. The component must not shift the selected date due to the local time-zone offset.

Focus Management

  • On open: Focus moves to the currently selected day in the grid. If no selection, focus moves to today.
  • On close: Focus returns to the input that opened the popover.
  • Tab order inside popover: Header chevrons → month/year label → grid (single focus target, internal arrow-key nav) → presets → footer buttons.
  • Focus trap: Tab at the end of the popover wraps to the top; Shift+Tab at the top wraps to the end. Focus must not escape the popover via keyboard while it is open.
  • Visible focus indicator: The focused day cell shows a 2px accent border (WCAG 2.4.7). This must not be overridden.
  • Clicking outside: Dismisses the popover and restores focus to the input.
Focus ring spec
Focused day cell: 2px Border-Accent ring. Focused input: 2px Border-Accent + 3px accent shadow (rgba(0,106,255,0.15)).
