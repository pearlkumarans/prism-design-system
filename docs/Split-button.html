Split Button

A split button gives the user a default action up front, with the close relatives tucked into a chevron next to it — “Save” on the left, “Save as draft / Save and publish” on the right. Reach for it when most users will take the same action 80% of the time but a few need a nearby alternative. For unrelated actions, use separate buttons.

Content GuidelinesRecommended

Do
  • Use Split Button for a primary action that has related secondary options (e.g., "Save" + "Save As...", "Save & Close").
  • Always pair with an Action Dropdown or menu that opens from the Chevron Part.
  • Keep the primary action label concise (1-2 words).
  • Use the prefix icon to reinforce the primary action meaning (e.g., "+" for create/add).
  • Position the Split Button where you would normally place a Primary button.
Don't
  • Don't use Split Button when there is no secondary action -- use a standard Primary button instead.
  • Don't use more than one Split Button per view/section.
  • Don't use Split Button for navigation actions.
  • Don't hide the only/critical action behind the chevron -- the primary action should always be the most common one.
  • Don't use the Loading state without disabling the dropdown interaction.
  • Don't mix Split Button with other Primary-styled buttons in the same button group.

Variants

The Split Button ships in two visual styles — primary (gradient) and outline — set via the variant attribute. Each then composes into content variants based on the combination of icon, label, loading, and disabled.

Style variants

Variant Usage Example
Primary (default) The high-emphasis default. Gradient fill, white label & icons. Use for the main action on a view.
Outline Lower emphasis. Transparent fill, 1px Border-Primary frame, dark (Text-Primary) label & icons. Use in toolbars or beside a primary action.

Content variants

Variant Usage Example
Icon + Label Default usage. Prefix icon reinforces the primary action (e.g., "+ Create").
Label only When the label is self-explanatory and an icon would add noise.
Loading Spinner replaces both parts while async action is pending. Both clicks are disabled.
Disabled Action and chevron both unavailable. Used for permission-gated or precondition-pending actions.

RTL (Right-to-Left)

For Arabic, Hebrew, and other RTL locales, the button parts mirror so the chevron sits on the left and the icon stays adjacent to the leading edge of the label.

LTR (default)
<ds-split-button icon="add" label="Create">
RTL
<ds-split-button icon="add" label="إنشاء" rtl>

Note: The Split Button uses CSS logical properties so most layout flipping happens automatically. The rtl attribute applies dir="rtl" to the inner container, which also reorders the action and chevron parts.

When and Where to Use

Reach for a split button when there’s one clear default action and a small set of close cousins (Save / Save as / Save and exit). Use a plain button when the action stands alone; a dropdown menu when the “default” itself isn’t obvious.

When to use

  • For a primary action that has related secondary options (e.g., "Save" + "Save As...", "Save & Close").
  • Compound actions in toolbars where space is constrained and secondary options need to be grouped.
  • Form submissions with variants (e.g., "Submit" + "Submit & New", "Submit & Close").

When NOT to use

  • When there is no secondary action needed -- use a standard Primary button.
  • For navigation actions -- buttons should trigger actions, not page transitions.
  • For a single simple action where no dropdown is warranted.

Complete Do's and Don'ts

Visual and interaction guidelines to ensure Split Buttons are effective, scalable, and accessible.

Do
  • Pair with dropdown: Always pair with an Action Dropdown or menu that opens from the Chevron Part.
  • Concise labels: Keep the primary action label to 1-2 words for clarity.
  • Use prefix icon: Reinforce the primary action meaning (e.g., "+" for create/add).
  • Consistent placement: Position where you would normally place a Primary button.
  • Primary action visible: The most common action should always be the button label, not hidden behind the chevron.
Don't
  • No secondary action: Don't use when there is no secondary action -- use a standard Primary button.
  • One per view: Don't use more than one Split Button per view/section.
  • Not for navigation: Don't use for navigation actions.
  • Critical actions: Don't hide the only/critical action behind the chevron.
  • Loading + dropdown: Don't use the Loading state without disabling the dropdown interaction.
  • Button mixing: Don't mix with other Primary-styled buttons in the same group.

Key Differences from Standard Button

Split buttons and plain buttons look related but behave differently. A plain button does one thing. A split button does the same default thing on the left, and opens a tiny menu of related options on the right — one component, two click targets.

  • Two distinct interactive zones: The Split Button has two separate clickable areas (Button Part + Chevron Part), unlike the standard Button which is a single target.
  • Icons always visible: Both prefix and suffix icons are always shown -- there is no boolean toggle to hide them like in the standard Button.
  • Divider is structural: The divider between parts is a structural element that separates the two interaction zones, not a decorative element.
  • Focus wraps entire component: The Focus state wraps the entire component with an outer ring (12px radius), unlike the standard button which wraps just the single button area.
  • Loading replaces entire content: The Loading state replaces both parts with a spinner, not just the label text.

Accessibility

Guidelines for ensuring all Split Button interactions are accessible across assistive technologies.

Compound Component Pattern

The Split Button is a composite widget consisting of two focusable zones: the primary action button and the dropdown menu trigger (chevron). Each zone must be independently operable via keyboard and screen reader. The button part triggers the primary action, while the chevron part opens a dropdown menu of secondary actions.

  • The Split Button should be treated as two adjacent but related controls, not a single button.
  • Each part must be a native <button> element to inherit default accessibility behaviors.
  • The visual grouping (shared container, continuous background) communicates the relationship between the two parts.

Keyboard Interaction

KeyAction
TabFocus moves to the primary action button part.
Enter / SpaceActivate the primary action (when button part is focused).
Tab or Arrow RightMove focus from the button part to the chevron part.
Enter / Space (on chevron)Open the dropdown menu.
EscapeClose the dropdown menu if open.

ARIA Attributes

Ensure the Split Button's dual interactive zones are properly communicated to assistive technologies.

  • The chevron/dropdown trigger must include aria-haspopup="menu" to indicate it controls a menu.
  • When the dropdown is open, the chevron must set aria-expanded="true"; when closed, aria-expanded="false".
  • The primary button part uses the standard role="button" (inherited from the native <button> element).
  • Consider using aria-label on the chevron button (e.g., "More actions") to describe its purpose to screen reader users.

Focus State Design

  • Focus ring: 2px solid using the primary accent color (#006AFF), wrapping the entire Split Button component.
  • Outer border radius: 12px, with a 4px gap between the focus ring and the inner container.
  • The inner container retains both Button Part and Chevron Part in their default state appearance.

Touch Target Size

Mobile and tablet platforms require specific tap areas to prevent accidental clicks.

The Large size (48px height) meets the minimum touch target requirement natively. Smaller sizes will have invisible padding added in mobile environments to meet iOS/Android touch spacing requirements. Both the button part and chevron part must independently meet minimum touch target sizes.
