Widget

The dashboard tile / panel container — a self-contained surface with a fixed chrome (header + optional footer) wrapping a swappable body. Set type to chart, list, or table and drop the matching component into the default slot; set it to error, empty, or no-data and the widget renders a built-in placeholder. The header carries a drag handle, title, optional info icon, a trend badge, a filter, and an action; the footer carries a summary + a "view all" link. selected adds the dashboard-edit ring + resize handles. It contains a <ds-chart> — it is never itself a chart.

Content types

The body swaps by type. Content types (chart/list/table) host slotted children; state types render a built-in ds-empty-state.

chart (default slot → ds-chart)
error / empty / no-data (built-in)
no-data + per-type empty (state-illustration="empty-bar")
list → property view (ds-description-list)

States & edit mode

The drag handle and resize handles are dashboard-edit affordances — they only exist when edit-mode is set, and then reveal on hover (or stay while selected). In view mode the widget shows no drag/resize chrome. All visual only; the frame has no click/keyboard behavior.

view mode — no chrome
edit-mode — hover to reveal
edit-mode + selected — persistent

Header controls

Every trailing control is optional and composes an existing component. Trend badge status recolors it; the filter is a ds-button outline; the action is a ds-icon-button.

trend + filter + action
success trend, no filter
info icon, no action

When to use

  • Any dashboard tile that needs a titled frame around a chart, list, or table with header controls (trend, filter, menu) and a "view all" footer.
  • A resizable/reorderable panel in an editable dashboard grid — use selected for the chosen tile.
  • A content region that must gracefully show error / empty / no-data placeholders without the host drawing them.

When not to use

  • A single metric value + trend (no chart chrome) — use ds-kpi-card.
  • A bare chart with no title/footer/surface — use ds-chart directly.
  • A generic content card that isn't a dashboard tile — use ds-card.

Composition — reuse, don't re-implement

Every interactive part is an existing component. The widget only owns the surface + layout.

Chart widget
HTML
<ds-widget type="chart" title="Drivers By Class"
  trend="12%" trend-status="critical"
  filter-label="Last 7 days" footer-summary="+41 more Drivers">
  <ds-chart type="column" mode="single"></ds-chart>
</ds-widget>
List widget — two shapes (pick by data)
HTML
<!-- A) Collection — a list of entities (icon + name + status) -->
<ds-widget type="list" title="Configurations" footer-summary="+41 more">
  <ds-list> … </ds-list>   <!-- or your own item rows -->
</ds-widget>

<!-- B) Property view — one entity's term→value details -->
<ds-widget type="list" title="Device details" footer-label="View device">
  <ds-description-list orientation="horizontal"></ds-description-list>  <!-- items set via JS -->
</ds-widget>

RTL

Header and footer are plain flex rows — dir="rtl" mirrors them for free (title moves right, controls move left, footer link to the visual left). No duplicate content props.

dir="rtl"

Basic usage

HTML
<ds-widget
  type="chart"          <!-- chart | list | table | error | empty | no-data -->
  title="Drivers By Class"
  trend="12%" trend-status="critical"
  filter-label="Last 7 days"
  footer-summary="+41 more Drivers" footer-label="View all"
  selected dir="rtl">
  <ds-chart type="column" mode="single"></ds-chart>  <!-- default slot -->
</ds-widget>

Roles & semantics

  • The frame is a static role="group" with an aria-label derived from title — not a button.
  • Header action, filter, and footer link are real <button>/<a> elements (via ds-icon-button / ds-button / ds-text-link) with their own focus rings.
  • selected is exposed via aria-selected="true" on the host — the ring color alone isn't sufficient for screen readers.
  • State illustrations are aria-hidden; the placeholder title/description are readable text and the "Retry" action is a real focusable button.

Keyboard

KeyAction
TabDrag handle → info → filter → action → body content → footer link, in DOM order (matches visual order in LTR and RTL).
Enter / SpaceActivates the focused control. The widget frame itself is never a tab stop.

Contrast & RTL

  • Text tokens (Text-Primary, Text-Secondary, Text-Quaternary) meet AA on the widget surface.
  • Trend badge conveys status with an arrow glyph + % label, not color alone.
  • dir="rtl" mirrors layout and focus order — the footer link moves to the visual left, matching reading order.
