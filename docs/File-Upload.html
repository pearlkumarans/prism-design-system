File upload

Lets users attach files by browsing or dragging & dropping, in two styles: Form — a 40px input-like field that sits inline with other form controls — and Prominent — a dashed drop zone for upload-centric screens. Both support single and multiple selection and walk each file through uploading → scanning → success / error with cancel, retry, and remove affordances.

Anatomy

1
Field / Drop zoneThe clickable, droppable container. Form: 40px solid field. Prominent: 78px dashed zone.
2
Placeholder / Hint“Choose file (or) drop here” (Form) or “Drag files here or” (Prominent). Text-Quaternary, 14px.
3
Browse / Upload buttonSecondary small (Form) or Primary xsmall (Prominent). Opens the OS file picker.
4
File rowOne per file: icon, name, then progress + %, “Scanning…”, or error text — plus cancel / retry / remove.
5
Summary rowMultiple type only: “Uploading files (2 of 5)…” with a chevron to collapse/expand the list.
6
Helper rowThe shared Form Field Helper Row. Follows the state: error → red + icon, success → green + tick.

When to Use

  • Form — one attachment inside a form, sitting inline with text fields and selects (e.g. “attach license file”).
  • Prominent — screens where uploading is the primary task (import wizards, bulk agent installers, evidence upload).
  • Don’t build ad-hoc drop zones — drag & drop, picker, progress, and error handling are all here.
  • Single type blocks a new pick while one file is in flight — cancel or remove it first (don’t silently replace).

Lifecycle & ownership

The component renders the UI; your code owns the upload. Listen for ds-file-upload-select, start your request, and drive el.files / el.updateFile() as bytes move. The visual state is derived: any error → error, any busy → uploading, all success → success.

StatusRow showsActions

Validation

  • Pass accept to pre-filter the OS picker — but always re-validate on select (drag & drop bypasses accept).
  • Reject oversize / wrong-type files before uploading: set the file to status:'error' with the reason in statusText, and echo it in helper.
  • Keep the helper line for constraints (“Only .csv files are supported”) — it doubles as the error/success message via the shared helper row.

RTL Support

Set rtl to mirror the layout (logical properties throughout). Provide localized placeholder / zone-hint / button-label / helper strings.

HTML + JS

Usage

Listen for the selection, run the upload yourself, and drive files as bytes move.

<ds-file-upload variant="prominent" multiple accept=".csv"
                helper="Only .csv files are supported"></ds-file-upload>

<script>
  const up = document.querySelector('ds-file-upload');
  up.addEventListener('ds-file-upload-select', (e) => {
    /* start your upload for each picked/dropped File… */
    up.files = e.detail.files.map((f) => ({ id: f.name, name: f.name, status: 'uploading', progress: 0 }));
  });
  /* …then report progress and outcomes: */
  up.updateFile('report.csv', { progress: 80 });
  up.updateFile('report.csv', { status: 'success' });
  up.addEventListener('ds-file-upload-cancel', (e) => up.removeFile(e.detail.file.id));
</script>

Accessibility

A visually-hidden native <input type="file"> does the picking, so the OS dialog and form semantics come for free.

  • The field/zone is a keyboard-reachable role="button" (tabindex="0") labelled with the placeholder text and described by the helper row (aria-describedby).
  • Drag & drop always has a click/keyboard equivalent — the whole zone and the Browse/Upload button open the picker.
  • Every row action carries the file name in its aria-label (“Cancel upload of report.csv”, “Retry upload of…”, “Remove…”).
  • The progress bar is a real role="progressbar" (via ds-progress-bar) with aria-valuenow.
  • The helper row is a live region: polite normally, assertive on error — error copy placed there is announced immediately.
  • Disabled sets aria-disabled="true" and removes the box from the tab order.
