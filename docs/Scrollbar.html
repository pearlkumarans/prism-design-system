Scrollbar

A custom overlay scrollbar — a thumb-only, theme-aware scroll indicator that floats over scrollable content instead of taking layout width. The track is a transparent rail; the pill thumb is the only visible part, computed at runtime from the viewport-to-content ratio. Works on both axes (vertical & horizontal), in two thicknesses (Thin / Regular), with cursor-presence auto-hide and RTL support — 6 variants × 2 orientations in Figma.

Anatomy

An overlay scrollbar is just two parts: a transparent full-length Track and a pill Thumb that fills the cross-axis and is positioned along the long axis to mirror scroll offset. A 2px accent Focus Ring appears on the thumb only when the scroll region holds keyboard focus.

Hover anywhere in this region and a pill thumb appears on the right edge. With autohide="false" it stays visible regardless of the cursor.

Best PracticesRecommended

Do
  • Attach a scrollbar to a region that already scrolls with the wheel and keyboard — it is a supplemental affordance.
  • Give the host a bounded size so it can establish a scroll viewport.
  • Prefer Regular on touch surfaces; Thin is fine on dense mouse-driven panels.
  • Let the thumb auto-hide on hover and stay visible while dragging or focused — the default behavior.
Don't
  • Use the scrollbar as the only way to scroll — keyboard and wheel must still work.
  • Render a filled groove or arrow step buttons — the track is transparent, overlay-only.
  • Clip the host's overflow so tightly that the 2px focus ring is cut off.

Auto-hide = cursor presence. The thumb is shown while the pointer is over the scroll region (fade in 80ms) and hidden when it leaves (fade out 200ms). It stays visible while the thumb is being dragged or while the region has keyboard focus. On touch it reveals on scroll and fades ~800ms after scrolling stops. autohide="false" = always visible.

When and Where to Use

Reach for the overlay scrollbar to indicate scroll position in a bounded region without spending layout width on a native gutter.

When to use

  • On a scrollable list or feed that overflows its container.
  • Inside a data table body, modal body, or side rail.
  • In code / editor panes where a thin, unobtrusive indicator suits dense content.
  • For horizontal galleries or timelines that overflow sideways.
  • When you want a consistent cross-browser look instead of the OS scrollbar.

When NOT to use

  • As the only scroll mechanism — keyboard and wheel must still work.
  • As a progress indicator — use a Progress bar.
  • As a range input — use a Slider.
  • On a region that doesn't actually overflow — it will render nothing anyway.

Alignment & Placement

Attach a scrollbar to a host that owns the scroll viewport — it floats over content rather than occupying layout width.

  • Lists & feeds: wrap the scroll region so the vertical bar tracks down the trailing (right in LTR) edge.
  • Data tables: use it on the body for vertical overflow and a horizontal instance for wide column sets.
  • Modal bodies: let the body scroll under a fixed header/footer; the overlay bar avoids a layout-shifting gutter.
  • Side rails: thin vertical bar for long navigation or filter rails.
  • Code / editor panes: Thin size keeps the indicator subtle against dense monospace content.

Complete Do's and Don'ts

Do
  • Keep keyboard & wheel working: the container is the accessible scroll path; the bar is supplemental.
  • Prefer Regular on touch: the larger thumb is easier to perceive on coarse pointers.
  • Bound the host: give it an explicit size so it establishes a scroll viewport.
  • Re-measure on change: the thumb recomputes on scroll, resize and DOM mutation — let it.
  • Name the region: add aria-label on the host when the scroll area needs a name.
Don't
  • Don't make it the only scroll path: never remove wheel/keyboard scrolling.
  • Don't enlarge it into a heavy groove: keep the track transparent and overlay-only.
  • Don't add arrow buttons: the design has no step arrows.
  • Don't clip the focus ring: avoid overflow:hidden that cuts the 2px outside ring.
  • Don't fight nested scroll: give each scroll area its own instance.

RTL Support

  • The vertical bar moves to the left edge in RTL (right edge in LTR).
  • Horizontal logic mirrors — the thumb's position origin flips; no separate RTL variants are needed (the thumb is visually symmetric).
  • Implemented with dir-aware logic and logical properties (inset-inline-start, inline-size / block-size).
  • Set the rtl attribute (the component reflects it to dir="rtl") or place the host inside an RTL ancestor.

Accessibility

The scrollbar is a supplemental affordance. The accessible scroll path is the keyboard and wheel on the scroll container; the thumb is decorative.

Keyboard Interaction

KeyAction
TabMoves focus to the scroll region — focusable (tabindex=0) only when there is overflow.
↑ ↓Scroll the region by a line (vertical).
← →Scroll the region by a line (horizontal).
PageUp / PageDownScroll by a viewport page.
Home / EndJump to the start / end of the content.
Wheel / trackpadScroll the region; the thumb reflects position 1:1.

The scroll region is focusable only while it overflows, so empty/short regions stay out of the tab order. When focused, the thumb shows the 2px accent focus ring.

ARIA Attributes & Screen Reader Guidance

  • Decorative thumb: a thumb that only mirrors native scroll is marked aria-hidden="true" — it is not announced.
  • Supplemental affordance: the scrollbar is never the only way to scroll; keyboard and wheel on the container satisfy operability.
  • Name the region: the focusable scroll container needs an accessible name — provide aria-label on the host (e.g. “Recent activity”).
  • Optional control role: if the thumb is promoted to a real control, use role="scrollbar" with aria-controls, aria-orientation, and aria-valuenow / valuemin / valuemax.
  • No focus trap: the thumb must never capture or hold keyboard focus.
  • Don't rely on the bar alone: scroll affordance is reinforced by content overflow and keyboard operability, not the thumb's subtle colour.

Focus State Design

  • Focus ring: 2px solid Border-Accent (#006AFF) on the thumb.
  • Trigger: shown on :focus-within / :focus-visible of the scroll region (keyboard focus).
  • Shape: fixed rounded-rect — 6px (Thin) / 9px (Regular), not the thumb's pill radius.
  • Don't clip it: the ring is an outside stroke, so the host must not clip overflow around the thumb.

Touch Target Size

Thumb hit area = its visible size, by design. Like the overlay scrollbars in VS Code, GitHub and macOS, the thumb's interactive area equals its 4–8px visible width — we deliberately do not add an enlarged hit target. This is acceptable because the scrollbar is supplemental: the keyboard and wheel on the container are the accessible path, so operability never depends on grabbing the thin thumb.
