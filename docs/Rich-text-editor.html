Rich Text Editor

The rich text editor is where the user writes anything with structure — an announcement, a ticket reply, an article, a knowledge-base page. They can bold, italicise, link, drop in lists, headings, images, and tables. Pick the Fixed toolbar for editors users open often (so the controls are always there); pick Floating for slim layouts where the toolbar should appear only when text is selected.

Content GuidelinesRecommended

Do
  • Keep the editor at 640 px or wider so the Fixed toolbar fits on one row.
  • Use Floating toolbar for compact inline editors (comments, chat).
  • Pair Error state with a helper-row message that explains the problem.
  • Use Read Only to display rich content outside an edit flow.
  • Persist formatting in a structured format (HTML or editor JSON).
Don't
  • Shrink below 640 px — the Fixed toolbar will wrap; switch to Floating instead.
  • Use Fixed inside a narrow side panel or drawer.
  • Show the red error border without helper text.
  • Use Disabled to show read-only content — it communicates "cannot interact right now".
  • Allow arbitrary HTML and inline <script> from pasted content.

Toolbar grouping rules

  • Group related actions with 1px vertical dividers: [Text format] | [Block format] | [Alignment] | [Insert] | [History].
  • Each icon must be 20px inside a 32px tap target. Use 16px icons for compact (small-size) editor instances.
  • Show tooltips on hover with the action label and keyboard shortcut: "Bold · ⌘ B".
  • The active state is a 1px blue ring around the icon button when the selection contains that formatting (e.g., bold icon highlighted while cursor is inside bold text).
  • Disable (greyed) icons for actions that don't apply to the current selection (e.g., heading dropdown when the cursor is in a code block).
  • The Floating toolbar shows only the most-used 5–7 actions; the Fixed toolbar shows the full set.

When and Where to Use

Rich Text Editor is designed for long-form, formatted content authoring.

When to use

  • For long-form, formatted content — descriptions, knowledge-base articles, announcements, email bodies, release notes.
  • When users need inline styles (bold/italic), block structures (headings, lists, quotes), or embedded objects (links, images, tables).
  • When content must be rendered later in a non-editable view.
  • When variable/token insertion ($variable$) is part of the authoring flow.

When NOT to use

  • Short single-line input — use Text Input Field.
  • Plain multi-line free text without formatting — use Text Area.
  • Code or scripting input with syntax highlighting — use Script Editor.
  • Markdown-only input where live preview is required — use a dedicated markdown editor pattern.

Choose the right toolbar based on the editing context.

Complete Do's and Don'ts

Guidelines for effective Rich Text Editor usage.

Do
  • Keep the editor at 640 px or wider so the Fixed toolbar fits on one row.
  • Use Floating toolbar for compact inline editors (comments, chat).
  • Pair Error state with a helper-row message that explains the problem.
  • Use Read Only to display rich content outside an edit flow.
  • Persist formatting in a structured format (HTML or editor JSON).
  • Allow vertical resize for long-form editing.
  • Use the Floating toolbar's arrow to point at the active selection.
  • Localise the placeholder, label, and helper strings in RTL mode.
  • Sanitise and paste-clean external content (strip styles, scripts).
Don't
  • Shrink below 640 px — the Fixed toolbar will wrap; switch to Floating instead.
  • Use Fixed inside a narrow side panel or drawer.
  • Show the red error border without helper text.
  • Use Disabled to show read-only content — it communicates "cannot interact right now".
  • Store pasted rich content as raw HTML without sanitisation.
  • Allow horizontal resize — widths should be layout-driven.
  • Leave the Floating toolbar arrow floating over unrelated content when selection is cleared.
  • Force English chrome inside an Arabic/Hebrew layout.
  • Allow arbitrary HTML and inline <script> from pasted content.

Accessibility

Guidelines for ensuring the Rich Text Editor is accessible across assistive technologies and input methods.

Editor Runtime

  • Use a proper editor runtime (ProseMirror, Lexical, TipTap, Slate). A bare contenteditable div without a framework will not meet WCAG.
  • The editable region should expose role="textbox" with aria-multiline="true".
  • Connect the visible label to the editable region via aria-labelledby. Do not rely on <label for> — contenteditable is not a form control.

Keyboard Interaction

ActionResult
TabMoves focus into the editor.
⌘/Ctrl+BToggle bold.
⌘/Ctrl+IToggle italic.
⌘/Ctrl+UToggle underline.
⌘/Ctrl+KInsert / edit link.
EnterNew paragraph.
Shift+EnterSoft break (line break within paragraph).
Alt+F10Focus the toolbar. Esc returns to the editor.
Tab inside listsIndent list item (does not trap focus by default).

Note: Tab inside the editor should not trap focus by default — use it to indent lists only when a list item has focus.

ARIA Attributes & Screen Reader Guidance

  • Validation: Set aria-invalid="true" in Error state; link the helper-row message via aria-describedby.
  • Read Only: Set aria-readonly="true" and remove edit controls. Use contenteditable="false".
  • Disabled: Set aria-disabled="true" and remove from the tab sequence. The editor is announced as "disabled" and cannot be focused.
  • Toolbar buttons: Toolbar buttons must be keyboard-reachable via Alt+F10. Buttons expose aria-pressed="true" when the current selection has that format applied.
  • Floating toolbar: When the floating toolbar appears, it must not steal focus. Announce only when the user explicitly opens it.
  • Semantic output: Expose headings as role="heading" with the correct aria-level, lists as role="list"/role="listitem". Verify your editor emits semantic HTML.
  • RTL: Set dir="rtl" on the root; the editor runtime must mirror toolbar order, list markers, and cursor movement.

Color ContrastWCAG AA Pass

All color combinations meet WCAG 2.1 AA contrast requirements.

  • Placeholder contrast: Text/Text-Placeholder ≥ 4.5:1 against BG-Primary-alt.
  • Focus border: Border/Border-Accent (2 px) must be visible independent of colour.
  • Focus ring: The 2 px accent border + blue focus shadow serves as the focus indicator. Do not remove either.
