Section Header

The Section Header is a compact heading that labels a section or sub-region inside a page — a card region, a settings block, a list group, a modal body section. It carries a title with an optional description, an optional trailing “View All” action link, optional full-width top/bottom dividers, and a “With Border” trailing rule whose description now drops to a full-width second row. Three sizes (Small / Medium / Large), RTL-aware — 42 Figma variants.

Anatomy

A Section Header is a vertical column: an optional full-width divider, a content row (title text group that fills the row, an optional trailing rule, an optional trailing action), and — in the “With Border” style — the description on its own full-width second row.

1 Title 2 Description 3 Trailing Action (Text Link) 4 Trailing Rule (“With Border”) 5 Full-width Divider
1
TitleThe section label. A real heading element (<h2>–<h6>), Semibold, Text-Primary. Always shown.
2
DescriptionOptional supporting line, Regular, Text-Secondary. Inside the text group in “With Description”; on a full-width second row in “With Border”.
3
Trailing ActionOptional Text Link (Primary, Medium — e.g. “View All”) pinned to the trailing edge of the content row.
4
Trailing RuleThe “With Border” style: a 1px Border-Tertiary rule that fills the width between title and action, centred on the title row.
5
Full-width DividerOptional 1px Border-Secondary rule above and/or below the whole header (Divider = Bottom or Top and Bottom). Decorative.

Content GuidelinesRecommended

Do
  • Use a short, descriptive noun phrase for the title (1–3 words).
  • Render the title as a real heading at the correct outline level for the page.
  • Pair the “View All” action with the section in its accessible name (e.g. “View all devices”).
  • Reach for the smaller sizes in dense lists, larger sizes for prominent page sub-regions.
Don't
  • Use the Section Header as the page-level title — use the Page Header instead.
  • Rely on the trailing rule or divider as the only signal of grouping; they are decorative.
  • Stuff a full sentence into the title; move detail into the description.

Style

Variants, states, sizes, colour and spacing tokens, corner radius, and typography that define the Section Header's visual language.

Variants (Style)

Three Style presets control which extras appear. With Border only exists with Divider = None.

VariantUsageExample
Default Title only (description hidden unless explicitly shown). The baseline label for a region.
With Description Title + description stacked in one text group; the action centres against the two-line block. No trailing rule.
With Border Title + a trailing 1px rule that fills the width beside the title + action on row 1, and the description on a full-width second row below.

States

The Section Header itself is static structure — it has no hover/focus/disabled state of its own. Only the trailing action link is interactive; it inherits Text Link states.

Header (Default)
Plain text and decorative rules. No interaction, no state change. Title and description are not focusable.
Action — Default
Accent-link colour #006AFF, no underline. Hugs the trailing edge.
Action — Hover
Underline appears (never colour-only). Colour transitions ~110ms ease.
Action — Focus
2px accent focus ring with 2px offset on :focus-visible.

When and Where to Use

Use a Section Header to label a sub-region inside a page. Reserve the Page Header for the page-level title.

When to use

  • To label a group of content inside a card or panel.
  • To head a settings block or a cluster of related fields.
  • To introduce a list group with an optional “View All” affordance.
  • To divide a modal body into labelled sections.
  • To title a page sub-region without competing with the page title.

When NOT to use

  • As the page-level title — use Page Header instead.
  • As a standalone separator — use a Divider.
  • As a collapsible heading — use an Accordion header.
  • As an inline link on its own — use a Link / Text Link.

Alignment & Placement

The header fills the width of its container; only vertical padding scales with size.

  • Inside cards / panels: sit the header flush to the card's inner padding so the title aligns with the content edge.
  • Settings blocks: use Medium or Large to group related fields; pair the description with the block's purpose.
  • List groups: use Small or Medium with a trailing “View All” action; add a bottom divider to separate from the list.
  • Modal body sections: use With Border to give a clear titled rule between sections without a heavy divider.
  • Page sub-regions: keep the size below the page title's so hierarchy stays clear.

Complete Do's and Don'ts

Do
  • Real heading: render the title as a real heading element at the right outline level.
  • Descriptive action: give “View All” an accessible name tied to the section.
  • Match size to density: Small in tight lists, Large for prominent sub-regions.
  • Use With Border for titled rules: when you want a rule that reads as “Title ───── Action” with the description below.
  • Keep it fluid: let the header fill its container; never hard-code 360px.
Don't
  • Don't overload the title: avoid full sentences; move detail to the description.
  • Don't rely on rules for meaning: dividers and the trailing rule are decorative only.
  • Don't mix With Border + dividers: With Border replaces stacked dividers (Divider = None).
  • Don't squeeze the action: keep the title group flexible so the title wraps before the action.
  • Don't use it as a page title: that's the Page Header's job.

Implementation Example

Ember / Handlebars usage — a “With Border” section heading a device list.

{{!-- MyApp/templates/components/devices-section.hbs --}}
<UemsSectionHeader
  @title="Connected Devices"
  @headingLevel={{2}}
  @size="medium"
  @description="All registered endpoints across your organisation"
  @border={{true}}
  @divider="none"
  @showAction={{true}}
  @actionLabel="View All"
  @onAction={{this.viewAllDevices}}
/>

RTL Support

  • The title and description lead from the right; the action and trailing rule move to the left.
  • Title and description text right-aligns to the trailing (right) side.
  • Use logical properties (padding-inline, margin-inline-start) so most mirroring is automatic.
  • Set dir="rtl" on the header or an ancestor; the action chevron is mirrored via transform: scaleX(-1).
  • Localize all strings (title, description, action label and its accessible name).

Accessibility

The header is static structure; the only interactive part is the trailing action link.

Keyboard Interaction

KeyAction
TabMoves focus to the trailing action link (the only focusable element). The title and description are not focusable.
Shift + TabMoves focus back to the previous focusable element.
EnterActivates the action link (navigates / fires the handler).
SpaceActivates the action when it is rendered as a <button>.

The header text itself is never focusable. Nothing auto-focuses. Focus order is: surrounding content → action link → next content.

ARIA Attributes & Screen Reader Guidance

  • Real heading: render the title as a real heading element (<h2>–<h6>) via heading-level, never a styled <span> — it joins the document outline.
  • Descriptive action name: a bare “View All” is ambiguous; pair it with the section, e.g. aria-label="View all devices".
  • Decorative rules: mark full-width dividers and the trailing rule aria-hidden="true" / role="presentation"; never the only signal of grouping.
  • Real link / button: render the action as an <a> or <button> so it is reachable and operable by assistive tech.
  • Description association: place the description immediately after the heading; if used as help text, associate via aria-describedby.
  • Don't rely on colour alone: the action shows an underline on hover/focus in addition to the accent colour.

Focus State Design

  • Focus ring: 2px solid using --uems-text-accent-link (#006AFF).
  • Offset: 2px from the action link's edge.
  • Border radius: 4px on the link's focus target (slightly larger than its text box).
  • Trigger: shown on :focus-visible so mouse clicks don't leave a lingering ring.

WCAG 2.1 Level AA Requires: a contrast ratio of at least 4.5:1 for normal text (like most component labels) and 3.0:1 for large text and UI components (like icons and focus rings).

Touch Target Size

Minimum target: 48×48px. The trailing action link is visually compact (14/20 text), so give it transparent padding and surrounding spacing so its hit area reaches at least 48×48px — especially in Small/Medium dense lists where the link's text height is well under 48px.
