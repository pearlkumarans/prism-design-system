Stepper

A progress indicator for a sequence of steps — horizontal or vertical. It shows where the user is, what's done, and what's ahead. Use it for multi-step tasks: checkout, setup assistants, "Deploy software" configuration, or any wizard body. The connector lives inside each step and fills as progress advances.

Anatomy

1
NodeThe circular indicator — a number, a check (completed), or the step's own label icon in numberless mode. Filled with an accent / success / error / warning token per state.
2
ConnectorThe line joining steps, rendered as part of each step (leading for horizontal, trailing for vertical). It fills up to the active step to show progress.
3
TitleThe step label. The active step's title turns accent and semibold.
4
DescriptionOptional secondary line beneath the title. Toggle off with hide-descriptions.
5
Stateupcoming · active · completed · error · warning · disabled — derived from active or set per step via status.

When to use

  • Guiding a user through an ordered, multi-step task (setup, checkout, deploy).
  • Showing progress and remaining work at a glance ("Step 2 of 5").
  • As the indicator inside a wizard — paired with step panels and a Back / Next footer.
  • Vertical when steps carry longer descriptions or the layout is a sidebar rail.

Do's and Don'ts

Do
  • Keep step labels short (1–2 words) and scannable.
  • Use error to block advancing until a step is fixed.
  • Use mode="linear" unless users can safely jump around.
Don't
  • Cram more than ~6 steps into a horizontal stepper — go vertical.
  • Let users click ahead in a linear flow — keep future steps locked.
  • Hardcode colours or spacing — everything comes from tokens.

Component API & Properties

Data is set via the .steps JS property: [{ id, label, description?, status?, icon?, optional?, disabled? }]. Status is derived from active unless set per step. icon is the step's label-based node icon, shown in numberless mode (hide-numbers); completed always shows a check.

AttributeTypeDefaultDescription
orientationhorizontal / verticalhorizontalLayout axis.
sizesm / md / lgmdNode + type scale (20 / 24 / 32px node).
activenumber0Current step index.
modelinear / nonlinearlinearLinear locks steps after active.
clickablebooleanunsetMake steps interactive (buttons).
label-placementbelow / inlinebelowHorizontal only — label under vs beside the node.
connectorsolid / dashed / nonesolidConnector style.
hide-numbersbooleanunsetNumberless mode — each step shows its own icon (label-based) instead of the number; completed still shows a check.
hide-labels / hide-descriptionsbooleanunsetHide the whole label block / hide just the description line.
rtlbooleanautoMirror (also auto-detected from [dir="rtl"]).

Methods: next(), prev(), goTo(i), setStatus(id, status). Emits ds-stepper-select → detail = { id, index, step }.

Usage

<ds-stepper id="wiz" active="1"></ds-stepper>
<script type="module">
  const el = document.getElementById('wiz');
  el.steps = [
    { id: 'account', label: 'Account', description: 'Sign in' },
    { id: 'details', label: 'Details' },
    { id: 'plan',    label: 'Plan' },
    { id: 'review',  label: 'Review' },
  ];
  el.addEventListener('ds-stepper-select', (e) => {
    console.log(e.detail.index, e.detail.id);
  });
  // Flag a failed step after validation:
  // el.setStatus('plan', 'error');
</script>

Accessibility

  • Root is role="list" with aria-label="Progress"; each step is a list item.
  • The current step carries aria-current="step"; error steps get aria-invalid.
  • A visually-hidden role="status" live region announces "Step N of M: <label>".
  • Interactive steps are real <button>s, keyboard-operable (Enter / Space); future steps are aria-disabled in linear mode.
  • Connectors are aria-hidden; colour pairs meet WCAG AA; node transitions respect prefers-reduced-motion.
