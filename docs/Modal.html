Modal

The general-purpose Modal is a left-aligned dialog — header, body, and footer — centered on a scrim, for forms, detail views, and multi-action tasks. It comes in three sizes (480 / 640 / 880) and supports a rich footer: a leading text link plus a right-aligned button group. For a short, intent-colored yes/no decision use Confirmation Modal; for a full-viewport flow use Fullscreen Modal.

Content GuidelinesRecommended

Do
  • Pick the size by content density — SM for short forms, LG for tables / rich content.
  • Name the primary button for its action ("Save", "Publish") — not "OK".
  • Keep the header to a clear title + one optional description line.
  • Let long content scroll inside the body; keep the header and footer pinned.
  • Put the safe action (Cancel) left of the primary in the footer group.
  • Return focus to the trigger when the modal closes.
Don't
  • Use a Modal for a simple yes/no — use Confirmation Modal.
  • Enable overlay-click dismissal for forms with unsaved input (it's off by default).
  • Stack modals on top of modals — route to a new step or a fullscreen flow.
  • Let the dialog exceed the viewport — scroll the body instead.
  • Hide the close affordance without giving another clear way out.
  • Cram a multi-step wizard into one modal — use Fullscreen Modal.

Usage

When to reach for the general Modal versus its siblings.

When to use

  • A focused task that interrupts the flow: a short form, a detail view, an edit dialog.
  • The content needs a title, body, and one or more actions in a footer.
  • The work fits in a 480 / 640 / 880 px dialog (with the body scrolling if needed).

When not to use

  • A short, irreversible yes/no decision — use Confirmation Modal.
  • A full-viewport, multi-step flow or editor — use Fullscreen Modal.
  • Non-blocking acknowledgement — use Toast or Inline message.
  • Persistent secondary content alongside the page — use a Right pane / side panel.

Accessibility

Guidelines for an accessible Modal across assistive tech and input methods.

Titlearia-labelledby points to the title element.
Description / bodyaria-describedby points to the description (or body when no description).
Leading iconaria-hidden="true" — decorative.

Keyboard & focus

KeyBehavior
EscDismiss the modal (emits ds-modal-close with reason esc).
Tab / Shift+TabCycles focus inside the dialog only — focus is trapped while open.
Click on overlayDismiss only when dismiss-on-overlay is set; off by default.
  • On open, focus moves to the first focusable element inside the dialog (or the dialog itself).
  • On close, focus returns to the triggering element (or returnFocusTo if set).
