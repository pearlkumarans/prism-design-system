Message Box

The Message Box is an in-app notification panel — a collapsible card that groups system messages under two tabs (Alerts and Information) and lists them as stacked message rows in a scrollable region. It is a composition: an Accordion disclosure shell, a horizontal Tab Bar switcher, a custom overlay scrollbar, and slotted Inline Alert rows. Title is fixed (“Notifications”); RTL-aware — 8 Figma variants.

Anatomy

A Message Box is a card with a fixed header (chevron + “Notifications” title + a Tab Bar switcher) over a collapsible body that holds a scrollable list of message rows, with an overlay scrollbar in the trailing gutter.

Message Box · tabs, state & RTL

Alerts — expanded (default)

The default state: Alerts tab active, body showing warning-styled rows in a scrollable list.

Information — tab active

Switching the active tab to Information swaps the visible list to info-styled rows. Counts in the tab labels reflect each group.

Collapsed — header only

Only the header renders. No tab is highlighted when collapsed; re-expanding restores the active tab.

RTL — mirrored

With rtl, the title and chevron lead from the right, the tab switcher and scrollbar move to the left, and rows mirror.

Content GuidelinesRecommended

Do
  • Group persistent notifications into the two tabs — Alerts for warnings/issues, Information for advisories.
  • Keep the active tab indicated only when expanded; show both tabs at rest when collapsed.
  • Hide the whole component when there are no messages — there is no empty state.
  • Pair each row's meaning with icon + text + accent bar, never colour alone.
Don't
  • Don't show an active tab while the panel is collapsed.
  • Don't render an empty panel when there are no messages.
  • Don't put blocking confirmations or destructive prompts inside a row — use a Modal.

States

The Message Box is a composition — it has no styling state of its own beyond Expanded/Collapsed and the active tab. Interaction states live in its sub-components (Tab Bar, Inline Alert rows, scrollbar). The live demos above show expanded, collapsed and active-tab behaviour.

When and Where to Use

Use the Message Box for persistent in-app notifications grouped under two tabs. Reserve transient feedback for a Toast and single inline messages for an Inline Message.

When to use

  • For persistent notifications a user can review at their own pace.
  • When messages fall into two clear groups — Alerts and Information.
  • When the list may be long and needs a scrollable region.
  • When users should be able to collapse the panel to reclaim space.
  • As a notifications centre opened from a header bell or similar.

When NOT to use

  • For transient feedback — use a Toast.
  • For a single inline message — use an Inline Message.
  • For blocking confirmations or destructive prompts — use a Modal.
  • When there are no messages — hide the component entirely.

Complete Do's and Don'ts

Do
  • Group by type: Alerts for warnings/issues, Information for advisories — rows follow the tab's type.
  • Keep tab counts live: update Alerts / Information counts as messages arrive or dismiss.
  • Collapse by default in dense shells: prefer Collapsed on narrow / crowded layouts.
  • Announce new messages: push arrivals into an aria-live region so screen readers hear them.
  • Let rows wrap: keep the panel fluid and never truncate the message body.
Don't
  • Don't highlight a tab when collapsed: both tabs sit at rest until expanded.
  • Don't render an empty panel: hide the whole component when there are no messages.
  • Don't nest blocking flows in rows: a row's action is a Text Link, not a modal trigger for destructive work.
  • Don't hard-code height/width: the panel is fluid; the scroll region is capped by a token.
  • Don't rely on colour alone: pair each row's type with an icon and text.

RTL Support

  • The title and chevron lead from the right; the tab switcher moves to the left.
  • The vertical overlay scrollbar moves to the left edge.
  • Message rows mirror: accent bar on the right, text right-aligns, row actions on the left.
  • Implement with dir="rtl" + logical properties; a single host dir should cascade — don't author per-element RTL CSS.
  • Counts / digits stay LTR within the RTL layout; localize all strings.

Accessibility

The Message Box layers three ARIA patterns — disclosure (expand/collapse), tabs (Alerts/Information), and a focusable scrollable list.

Keyboard Interaction

KeyAction
Enter / SpaceOn the header button: toggles Expanded ↔ Collapsed.
TabMoves focus header button → tabs (Alerts → Information) → into the body list (row links, dismiss) → out.
← / →Switches the active tab when focus is in the tablist.
Home / EndMoves to the first / last tab in the tablist.
↑ / ↓Scrolls the focused message list by a line.
PageUp / PageDownScrolls the list by a page.
Home / End (in list)Jumps to the top / bottom of the message list.

Focus order is logical and never trapped. The scroll region itself is focusable (tabindex=0) and keyboard-scrollable so the list is reachable without a pointer.

ARIA Attributes & Screen Reader Guidance

  • Disclosure: the header control is a <button> with aria-expanded reflecting State and aria-controls pointing at the body id.
  • Tabs: render the switcher as role="tablist" with role="tab" (aria-selected) per tab and the list as the matching role="tabpanel" (aria-labelledby the active tab).
  • Focusable scroll region: the scroll container is tabindex=0 with an accessible name (aria-label, e.g. “Alerts”), keyboard-scrollable.
  • Live announcements: push new messages into an aria-live="polite" region; critical ones via assertive / role="alert".
  • Decorative chrome: the chevron and the scrollbar thumb are decorative (aria-hidden); the keyboard/wheel path is the accessible one.
  • Not colour alone: each row conveys its type via icon + text + accent bar, not colour by itself.
  • RTL: mirror via dir="rtl" + logical properties; counts/digits stay LTR within the layout.

Focus State Design

  • Focus ring: 2px solid accent ring on the header button, each tab, the scroll region, and row links.
  • Offset: 2px from each focus target's edge.
  • Trigger: shown on :focus-visible so mouse clicks don't leave a lingering ring.
  • Roving tabstop: within the tablist only the active tab is in the tab order; arrows move between tabs.

WCAG 2.1 Level AA Requires: a contrast ratio of at least 4.5:1 for normal text and 3.0:1 for large text and UI components (icons, focus rings, accent bars). Accent bars are non-text indicators always paired with icon + text.

Touch Target Size

Minimum target: 48×48px. The chevron / header button, each tab, and row action links read compactly — give them transparent padding and surrounding spacing so each hit area reaches at least 48×48px, especially on touch.
