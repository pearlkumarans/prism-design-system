Content GuidelinesRecommended

Do
  • Reflect the real page hierarchy in the trail.
  • Mark only the last item as Current (bold).
  • Keep labels concise and meaningful (e.g. "Settings", "Profile").
  • Use the home icon for app root level entries.
Don't
  • Show the user's click history instead of the actual path.
  • Bold or highlight intermediate items.
  • Truncate labels mid-word with ellipsis; abbreviate instead.
  • Place the home icon on every item.

Style

Design tokens, color mappings, and spacing tokens that define the Breadcrumb's visual language.

Variants

The component set contains 12 variants across three axes: Count, Overflow, and RTL.

AxisValuesDescription
Count2, 3, 4, 5Number of breadcrumb levels shown
OverflowFalse, TrueCollapses middle items into ··· (only for Count 4 and 5)
RTLFalse, TrueReverses item order with ‹ separators and Arabic text

Overflow behaviour: When Overflow=True, middle items are hidden and replaced with a ··· ellipsis token, keeping the first and last two items visible.

When and Where to Use

A breadcrumb trail shows the user's current position within a page hierarchy and provides quick navigation back to parent pages.

When to use

  • To show a user's position within a multi-level hierarchy (e.g. settings, category pages, admin dashboards).
  • When users need a reliable way to navigate back to parent pages without the browser back button.
  • In deep navigation trees with 3 or more levels.

When NOT to use

  • For flat, single-level navigation — a back link or tab bar is more appropriate.
  • When the path has only one level above the current page — a back link is sufficient.
  • As a primary navigation mechanism; breadcrumbs are supplementary wayfinding.

Alignment & Placement

Consistent placement makes breadcrumbs predictable and easy to find.

  • Page Headers: Place breadcrumbs above the page title within the page header area, left-aligned.
  • Admin Dashboards: Position below the top navigation bar and above content area for consistent context.
  • Mobile: Consider collapsing to show only the parent and current page, using overflow for deeper paths.
  • Settings Pages: Place at the top of the content panel to show the full settings hierarchy path.

Complete Do's and Don'ts

Visual and interaction guidelines to ensure breadcrumbs are effective, scalable, and accessible.

Do
  • Reflect true hierarchy: The trail must mirror the actual page structure, not user click history.
  • Use overflow for deep paths: Enable Overflow=True for 4+ level paths in space-constrained layouts.
  • Show home icon at root: Use Show Home Icon=ON for the first item when it represents the app root.
  • Use RTL variant for RTL locales: Apply the RTL variant for Arabic, Hebrew, and other RTL languages.
  • Keep labels concise: Use short, recognizable page titles (1-3 words) for each breadcrumb item.
Don't
  • Don't show click history: Breadcrumbs represent structure, not navigation history.
  • Don't bold intermediates: Only the Current (last) item should be bold and non-interactive.
  • Don't truncate mid-word: Avoid clipping labels with … mid-word. Abbreviate the label instead.
  • Don't place home icon everywhere: The home icon belongs only on the first item.
  • Don't manually mirror for RTL: Use the RTL variant; don't apply CSS transforms to an LTR breadcrumb.

Children API

Each direct child becomes a breadcrumb item. The last child is treated as the current page (gets aria-current="page", bolded, non-interactive). Earlier children stay as real <a> elements so routing libraries keep working.

<ds-breadcrumb home-icon>
  <a href="/">Settings</a>            <!-- default link -->
  <a href="/security">Security</a>     <!-- default link -->
  <span>Password Policy</span>         <!-- current (auto-marked) -->
</ds-breadcrumb>

Implementation Idea: Ember Hook Form

A common pattern in Ember applications involves dynamically building breadcrumbs from the route hierarchy.

<!-- MyApp/templates/components/page-breadcrumb.hbs -->
<UemsBreadcrumb
  @count={{this.breadcrumbItems.length}}
  @overflow={{this.shouldOverflow}}
  @showHomeIcon={{true}}
>
  {{#each this.breadcrumbItems as |item|}}
    <UemsBreadcrumbItem
      @label={{item.label}}
      @href={{item.route}}
    />
  {{/each}}
</UemsBreadcrumb>

RTL Support

  • When RTL = True, the full layout is mirrored — item order reverses and separators change from › to ‹.
  • Set dir="rtl" on the <nav> wrapper; do not rely on CSS alone.
  • Text content is in Arabic by default when RTL is enabled. All spacing and padding values mirror automatically.

Accessibility

Guidelines for ensuring breadcrumb navigation is accessible across all assistive technologies.

Keyboard Interaction

KeyAction
TabMove focus to the next breadcrumb link (Default items only). Current item is not focusable.
Shift + TabMove focus to the previous breadcrumb link.
EnterActivate the focused breadcrumb link and navigate to that page.

ARIA Attributes & Screen Reader Guidance

Ensure breadcrumb intent is explicitly communicated to all assistive technologies.

  • Landmark: Wrap in <nav aria-label="Breadcrumb"> to identify it as a navigation landmark.
  • List structure: Render items as an <ol> with <li> elements so screen readers announce "list of N items".
  • Current page: Add aria-current="page" to the last (Current) item; do not make it a link.
  • Overflow token: The ··· token should have aria-label="More items" and be expandable if interactive.
  • RTL: Set dir="rtl" on the <nav> wrapper to ensure correct reading order.

Focus State Design

  • Focus ring: 2px solid using the brand accent color (#2563EB).
  • Focus ring offset: 2px from the item text, with 4px border-radius.
  • Current item is non-interactive and does not receive focus.
  • Overflow token (···) receives focus only if it is interactive (expandable).
