Toggle

A toggle is for a single on/off setting that takes effect the moment the user flips it — Wi-Fi, notifications, dark mode, auto-save. Use a toggle for instant settings. Use a Checkbox when the answer is part of a form the user has to submit; use a Radio group when there are more than two options.

Content Guidelines

Specifics — how to label a toggle, when to add On/Off text, when to confirm a flip. Each rule has a reason; read both before you bend one.

Do
  • Use for immediate-effect settings (e.g., enable notifications)
  • Pair with a clear external label describing what the toggle controls
  • Use Show Text mode for audiences unfamiliar with toggle conventions
  • Use Large size for touch-first interfaces
  • Reflect the toggled state immediately in the UI
Don't
  • Don't use when action requires a form submit -- use Checkbox instead
  • Don't use for multi-value choices (use Radio or Select)
  • Don't rely solely on track color to convey state -- use text labels when needed
  • Don't disable without providing an explanation or tooltip
  • Don't use for destructive actions without a confirmation step

Toggled States

On and Off look distinct on purpose — the user has to be able to tell them apart at a glance, even without colour. Blue plus thumb-on-right reads as “active”; grey plus thumb-on-left reads as “not yet.”

When to Use

Reach for a toggle when the change is binary, instant, and persistent — the user flips it and the setting takes effect right away. For form questions answered later on submit, use a Checkbox.

When to use

  • Immediate-effect settings (e.g., dark mode, notifications)
  • User preferences that take effect instantly
  • Feature flags or capability toggles in admin panels
  • Inline controls embedded within list rows or cards

When NOT to use

  • Form-based binary inputs that require submission -- use Checkbox
  • Multi-value choices (more than 2 options) -- use Select or Radio
  • Non-binary options or ranges -- use Slider or Select

Toggle vs Checkbox

Toggle and checkbox can both be on/off — what tells them apart is timing. A toggle changes the setting the moment the user flips it. A checkbox stores the answer until the user submits the form.

AspectToggle / SwitchCheckbox
Effect timingImmediate -- change applies instantlyDeferred -- requires form submission
Value typeOn/Off (binary state)Checked/Unchecked (selection)
Common useSettings, preferences, feature flagsForm fields, terms acceptance, filters
Label positionExternal or inline textAlways adjacent label

Show Text Guidelines

In-track text is helpful when the colour alone isn’t enough — on small screens, for colour-vision users, or in regions where blue doesn’t read as “on.” Keep it off when the row already names the setting clearly.

  • Use text labels when the toggle is used by audiences unfamiliar with toggle UI conventions (e.g., non-technical users).
  • Use text labels when the toggle appears in isolation without a nearby descriptive label.
  • Omit text labels in dense UI layouts where space is limited and the toggle purpose is obvious from context.
  • Omit text labels for Small size toggles where text would be too small to read comfortably.

RTL Support

In Arabic, Hebrew, and Persian, the toggle mirrors automatically. The thumb sits on the right when off and slides left to turn on — matching how RTL users read the rest of the row.

  • In RTL mode, the thumb position is mirrored: Off = right, On = left.
  • The track shape and dimensions remain unchanged.
  • Text labels ("On"/"Off") are repositioned to match the mirrored layout.
  • External labels should also follow RTL text direction.

Implementation Example

Example Ember component usage for the Switch.

Ember / Handlebars 
// switch-toggle.hbs
<UemsSwitch
  @size="md"
  @toggled={{this.isEnabled}}
  @showText={{true}}
  @disabled={{this.isLocked}}
  @direction="ltr"
  @onChange={{this.handleToggle}}
/>

// controller.js
import Controller from '@ember/controller';
import { tracked } from '@glimmer/tracking';
import { action } from '@ember/object';

export default class SettingsController extends Controller {
  @tracked isEnabled = false;
  @tracked isLocked = false;

  @action handleToggle(newValue) {
    this.isEnabled = newValue;
  }
}

Accessibility

Most accessibility is built in — this section explains what your users get for free, and the few things you have to provide: a written label and an ARIA role that lets screen readers announce on/off correctly.

Keyboard Interaction

How the Switch responds to keyboard input for full accessibility.

KeyAction
TabMove focus to the switch
Space / EnterToggle the switch value between on and off
Shift + TabMove focus backwards to the previous focusable element

ARIA Attributes

Required ARIA roles and properties for screen reader support.

  • Use role="switch" on the toggle element with aria-checked="true" or aria-checked="false" reflecting the current state.
  • Provide an accessible name via aria-label or by associating a visible <label> element using for/id.
  • When disabled, set aria-disabled="true" on the switch element.
  • Avoid using role="checkbox" -- the switch role communicates immediate-effect semantics to assistive technology.

Focus State Design

Visual focus indicator specifications for keyboard navigation.

Focus Ring: 2px solid #006AFF with 2px offset
A visible ring surrounds the track to indicate keyboard focus. The 2px white gap ensures the ring is visible against the track color.

Color Contrast

WCAG 2.1 Level AA compliance for the Toggle component.

PASS On track (#006AFF) with white thumb -- contrast ratio 4.7:1
PASS Off track (#C3C9D6) with white thumb -- 3:1 UI component ratio

WCAG 2.1 Level AA Requires: A contrast ratio of at least 3.0:1 for UI components and graphical objects. The Switch thumb against both track colors meets this requirement.

Touch Target Size

Mobile and tablet platforms require specific tap areas to prevent accidental clicks.

48px
Minimum Target: 48 x 48 px
Small and Medium size switches include invisible padding to ensure the touch target meets the 48px minimum on mobile platforms. The Large size naturally meets this requirement.
