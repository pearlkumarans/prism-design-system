KPI Cards

A KPI card surfaces one headline number the user cares about right now. The system ships two live web components: <ds-kpi-card> is the metric family (size="default" / "wide") for a single value with an optional subtitle, trend badge, leading icon, date selector, gauge, or link; <ds-kpi-breakdown> is the severity family (layout="compact" / "stacked" / "wide") — a header stat plus a fixed 4-cell Critical / High / Medium / Low grid. Both are self-contained surfaces (they own radius 16, padding 20, border, background) and re-theme from --uems-* tokens. The host dashboard owns empty / error states.

Two elements

The Figma set's 94 variants resolve into two structural families, shipped as two custom elements that share an internal stat header.

<ds-kpi-card> — metric
size="default | wide". One headline value + the type matrix (icon, subtitle, trend, date selector, gauge, link).
<ds-kpi-breakdown> — severity
layout="compact | stacked | wide". A header stat + a fixed 4-cell Critical / High / Medium / Low grid; counts via the .data property.

Content GuidelinesRecommended

Do
  • Keep titles short — 1–3 words, sentence case; match them across cards in the same row.
  • Quantify the comparison in the subtitle ("Up 12% vs. last week"), not vague phrases.
  • Pick the element by intent — ds-kpi-card for one number, ds-kpi-breakdown for a severity split.
  • Reserve state="alert" for genuinely actionable bad news.
  • Let the card fill its dashboard grid cell; pick size for grid density.
Don't
  • Apply alert just because a number is low — context matters more than direction.
  • Pack multiple numbers into one metric card — use ds-kpi-breakdown instead.
  • Recolor the value per state — value & title color stay constant; only badges recolor.
  • Render an empty / error placeholder inside the card — the host dashboard owns it.
  • Mix sizes/layouts in a single row — visual rhythm breaks.

Usage

Which element to reach for, and how the KPI card shares the data lifecycle with its host dashboard.

Picking the element

You have…Use
One headline number (with optional trend, gauge, date, link)ds-kpi-card
A column / bar chart's single value pulled up as a tileds-kpi-card
One total that splits across Critical / High / Medium / Lowds-kpi-breakdown
A trend over time, or more than ~4 categoriesds-chart (not a KPI card)

Picking the size / layout

QuestionChoice
Dense dashboard grid (4-up summary row)?ds-kpi-card size="default"
Long title/subtitle, a trailing link, or a full-width row?ds-kpi-card size="wide"
Compact severity tile in a grid?ds-kpi-breakdown layout="compact"
Roomier severity card?ds-kpi-breakdown layout="stacked"
Full-width severity banner (header left, cells right)?ds-kpi-breakdown layout="wide"

State ownership

The host dashboard owns the data lifecycle. Empty and error states are rendered by the host using the system Empty state component — consistently across all widget content (chart, table, KPI). A KPI card owns only its loading skeleton; it never draws an empty or error placeholder itself.

Do & Don't

Do
  • Pull a column / bar chart's single value into a ds-kpi-card for at-a-glance reading.
  • Use ds-kpi-breakdown when one total splits across severities.
  • Pick size / layout for grid density; let the card fill its cell.
  • Keep values legible — short titles, quantified subtitles.
  • Let the host render empty / error via the Empty state.
Don't
  • Cram many types into one row — keep a row visually consistent.
  • Recolor the value per state — only the icon & trend badges recolor.
  • Handle empty / error inside the card — the host owns it.
  • Use a gauge as decoration when there's no implied total.
  • Reach for ds-kpi-breakdown for non-severity splits — use a chart.

Breakdown & the .data property

Set severity counts on the JS property after the element is defined. Values can be plain numbers, or { value, label, href } objects (the href renders a "View" link in layout="wide").

HTML + JS
<ds-kpi-breakdown id="vuln" layout="compact" value="1,558"
  title="Total Vulnerabilities" subtitle="Across all severity levels"></ds-kpi-breakdown>

<script type="module">
  customElements.whenDefined('ds-kpi-breakdown').then(() => {
    document.getElementById('vuln').data = { critical: 139, high: 102, medium: 422, low: 123 };
  });
</script>

Clickable card with event handler

HTML + JS
<ds-kpi-card id="comp" state="success" value="98%"
  title="Compliance" subtitle="Click for breakdown" icon="check" clickable></ds-kpi-card>

<script>
  document.getElementById('comp').addEventListener('ds-kpi-card-select', (e) => {
    console.log(e.detail);  // { source, label, value }
  });
</script>

The gauge/chart slot always renders the shared <ds-chart> component (type="gauge" or "line") — never a bespoke SVG. Known limitation: ds-chart keeps its text at a fixed readable size regardless of container width, so at the compact gauge-position="end" width (80px) the gauge's "%" text can crowd the small arc. gauge-position="bottom" (full card width) gives the chart enough room and is the recommended choice for chart-type="line".

Accessibility

Guidelines for accessible KPI cards across assistive tech and input methods.

Roles & ARIA

ConcernImplementation
Card rootds-kpi-breakdown is a role="group" with an aria-label summarizing the stat ("Total Vulnerabilities, 1,558"). A clickable ds-kpi-card becomes role="button" with tabindex="0" and an auto aria-label="{title}, {value}".
Value & titleReal text in DOM order (title is an <h3>) — read by screen readers, not painted as background.
TrendConveyed by icon + text + color, never color alone; trend-sentiment sets the accessible meaning.
GaugeDecorative (aria-hidden="true"); its meaning lives in the surrounding text.

Keyboard & interactive parts

ElementBehavior
Clickable cardTab to focus; Enter / Space activate (fires ds-kpi-card-select). Don't nest other interactive elements inside.
Date selectorA real <button> (with aria-haspopup="menu" when wired) — keyboard operable, visible focus ring.
LinkA real <a> with href — standard focus ring and activation.
Severity cellsReal <button>s labeled by their count + severity; each fires ds-kpi-breakdown-select.

Color contrastWCAG AA pass

ConcernRequirement
Text on surfaceAll text tokens on --uems-bg-primary-alt meet WCAG 2.1 AA; severity counts verified on their tinted boxes.
Color not the sole signalSeverity cells pair color with the text label; state pairs color with wording.
Reduced motionprefers-reduced-motion: reduce collapses the gauge sweep and loading shimmer to instant updates.
