Icon Button

An icon button stands in for a text button when the meaning is obvious from the symbol — close, edit, more, delete — and you don’t have the room for a label. Reach for it in toolbars, table row controls, and dense card headers. The icon has to do the work of the label, so always pair it with an aria-label for screen readers and a tooltip for sighted users hovering to confirm what it does.

Content GuidelinesRecommended

Do
  • Always provide an aria-label that describes the action.
  • Use universally recognized icons (close, add, edit, delete).
  • Use tooltips to show the action label on hover.
  • Match icon button type to the Button type used nearby for consistency.
  • Use the circle shape for FAB-style (floating action button) actions.
Don't
  • Don't use icon buttons for ambiguous or uncommon actions without a tooltip.
  • Don't use when the action needs a text label for clarity -- use a Button instead.
  • Don't mix square and circle shapes in the same toolbar.
  • Don't use danger type for non-destructive actions.
  • Don't disable without providing a reason via tooltip.

RTL (Right-to-Left)

Most icons (close, add, edit, delete, search) are visually symmetric and need no flipping. Directional icons — those that point or imply motion — must be mirrored in RTL contexts.

Icons that flip in RTL

IconLTR meaningRTL behavior
chevron-left / chevron-rightPrevious / NextSwap names: use chevron-right for Previous, chevron-left for Next.
arrow-left / arrow-rightBack / ForwardSwap names. Or apply CSS transform: scaleX(-1) on the icon.
caret-left / caret-rightOpen / Close drawerSwap names.
reply / forwardReply / Forward messageMirror via scaleX(-1).
undo / redoUndo / RedoMirror via scaleX(-1) to flip arrow direction.
send / send-planeSend messageMirror via scaleX(-1) so the plane points toward the leading edge.

Icons that DO NOT flip

Symmetric icons stay unchanged: close, add, delete, edit, search, info-circle, check, bell, user, settings, more-horizontal, more-vertical. Logos and brand marks should also stay unchanged regardless of direction.

CSS pattern for auto-flip

/* In your component CSS — flip directional icons in RTL */
[dir="rtl"] .my-icon--directional {
  transform: scaleX(-1);
}

When and Where to Use

An icon button triggers an action using a single icon without a text label, ideal for space-constrained interfaces.

When to use

  • Toolbar actions where space is limited and icons are universally understood (edit, delete, close).
  • Inline controls alongside other elements (close button on a tag or card).
  • Toggle or secondary actions that don't require a text label.
  • Repeated actions in data tables or list rows (row-level edit, delete).
  • Floating action triggers (plus button to add an item).

When NOT to use

  • For ambiguous or uncommon actions without a tooltip.
  • When the action needs a text label for clarity -- use a Button instead.

Best Practices

Visual and interaction guidelines to ensure icon buttons are effective, scalable, and accessible.

Do
  • Always provide an aria-label that describes the action, not the icon (e.g., "Delete item" not "Trash icon").
  • Use universally recognized icons (close, add, edit, delete) to ensure immediate comprehension.
  • Use tooltips to show the action label on hover for sighted users.
  • Match icon button type to the Button type used nearby for visual consistency.
  • Use circle shape for FAB-style (floating action button) actions.
Don't
  • Don't use for ambiguous actions without a tooltip to clarify the intent.
  • Don't use when action needs text -- use a full Button component instead.
  • Don't mix shapes in the same toolbar (square and circle).
  • Don't use danger type for non-destructive actions.
  • Don't disable without reason -- provide explanation via tooltip.

Accessibility

Guidelines for ensuring all icon button interactions are accessible across assistive technologies.

aria-label

Required on every icon button. Must describe the action, not the icon.

  • Every icon button must have an aria-label attribute that describes the action (e.g., "Delete item" not "Trash icon").
  • The aria-label must be concise and action-oriented. Screen readers announce the button as "button" role with the aria-label text.
  • For disabled states, use aria-disabled="true" to keep the button focusable so tooltips can explain why it is disabled.

Keyboard Interaction

KeyAction
TabMove focus to the icon button.
Enter / SpaceActivate the focused icon button.

Screen Reader Guidance

  • Icon buttons are announced as "button" role with the aria-label text.
  • Disabled state is communicated via aria-disabled.
  • Show a text tooltip on hover/focus to make the action discoverable for sighted users.

Focus State Design

  • Focus ring: 2px solid, offset 2px from the container edge.
  • Focus ring color: #0C66E4 (brand blue).
  • Background retains the Default state color during focus.

Touch Target Size

Minimum and recommended tap areas for mobile and tablet platforms.

28
WCAG 2.2 minimum: 24x24px | XL (28px) passes; Small (20px) & XSmall (16px) need an extended hit area
XSmall (16px) and Small (20px) are below the 24x24px WCAG 2.2 pointer-target minimum — when used standalone, extend the hit area (e.g. a ::before overlay or margin-compensated padding). Inside dense composites (Tag close, table rows) the parent provides context. XL (28px) and Large (24px) meet the minimum.
