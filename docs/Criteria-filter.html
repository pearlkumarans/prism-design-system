Criteria Filter

An advanced / criteria filter (expression builder). It assembles a list of field → operator → value conditions joined by AND/OR, optionally nested into groups with NOT, and emits a structured, JSON-serializable query tree. Sibling of the Filter panel (which is faceted); this is the expression tier. The host owns the query — the builder only reports state.

Anatomy

Header — title, a left-aligned Saved filters picker (load), and Clear all (a text link that resets to one fresh row); overlay modes add a close ✕. Body — condition rows (field ▾ · operator ▾ · value · duplicate · delete); in the default combinator structure they sit under a Match all / any combinator, with nested groups (each with a Not toggle) and Add condition / Add group. Invalid rows show a dashed error outline + helper. Optional query preview (summary + removable chips). Footer (apply-mode) — Cancel · Save & apply · Apply; where saving prompts for a name just above the footer (in live/inline mode the save button sits in the header instead). This live demo runs inline with show-preview, allow-field-source, and saved filters on.

Presentation modes

Inline

In-flow block — the default. Ideal inside a form (e.g. a dynamic group's membership) or above a data surface.

Popover

Anchored flyout from a “Filter” button. Light-dismiss (outside click / Esc). Pairs with a data table's filter icon.

Drawer

Off-canvas end-docked sheet with a scrim for large queries. Esc / backdrop close.

Structure

combinator (default) uses a "Match all / any of the following" combinator; advanced is a lead word + per-row And/Or + a criteria pattern. grouping toggles nested groups on/off for either — default on for combinator, off for advanced.

Operators by field type

Field typeOperatorsValue editor
textcontains, does not contain, starts/ends with, matches regex, equals, does not equal, is empty, is not emptyds-text-input
numberequals, ≠, <, ≤, >, ≥, between, not between, is empty, is not emptyds-text-input (×2 for between)
date / datetimeis, is not, before, after, between, is empty, is not emptyds-date-picker (show-presets)
booleanis true, is false— (operator carries it)
selectis, is not, equals, does not equal, is empty, is not emptyds-input-select
multiselecthas any of, has all of, has none of, is emptyds-token-field

Each operator has an arity: 0 = unary (no editor) · 1 = single value · 2 = range. Pass a custom operators array to replace the catalog.

Advanced conditions variant

structure="advanced" renders a flat list: the first row is led by a word (lead-word, e.g. When / Where), every later row starts with a small And / Or joiner select, and a criteria pattern line (e.g. 1 AND 2 OR 3) sits at the bottom. Each row carries a joiner in the emitted query. Add grouping="on" to allow nested groups (advanced-style, per-row joiners) — a nested group joins its sibling with an And / Or on its first row; when any group exists the criteria pattern turns off.

When to use

  • Reach for it when a filter is an expression — arbitrary field · operator · value conditions the user composes (dynamic groups, saved searches, report criteria, alert rules).
  • For picking values from a fixed set of facets, use the Filter panel instead; for a quick single-select slice, use the Tab filter.
  • Use combinator (default) for a "Match all / any" filter; keep grouping on when users need AND/OR nesting, or set grouping="off" for a simple single-level list.
  • Use live mode for client-side surfaces (instant), apply mode for server queries (batch on Apply).
  • Let the host own persistence: read the emitted query tree and map it to your query / API. Setting presets (even []) turns on the saved-filter UI — a left-aligned Saved filters picker (load) and, in apply-mode, a Save & apply footer button that validates first, then prompts for a name and fires preset-save { label, query }. Persist it and feed the updated list back.

Pairing with a data table

Open a mode="popover" builder from the table's toolbar filter icon; its change / apply event feeds table.rows. Reference page: projects/custom-groups/layout-create-group.html (dynamic Custom Group membership).

cf.addEventListener('ds-criteria-filter-change', e => {
  if (e.detail.valid) table.rows = runQuery(e.detail.query);   // host owns the query
});

HTML + setup

Usage

<ds-criteria-filter id="cf" title="Filter criteria"></ds-criteria-filter>
<script type="module">
  cf.fields = [
    { name:'hostname', label:'Host name', type:'text' },
    { name:'os', label:'Operating system', type:'select',
      options:[ {label:'Windows',value:'win'}, {label:'macOS',value:'mac'} ] },
    { name:'riskScore', label:'Risk score', type:'number' },
    { name:'lastSeen', label:'Last seen', type:'date' },
  ];
  cf.query = { combinator:'and', rules:[ { field:'os', operator:'is', value:'win' } ] };
  cf.addEventListener('ds-criteria-filter-change', e => {
    if (e.detail.valid) table.rows = runQuery(e.detail.query);
  });
</script>

Data model

type FieldDef = {
  name: string; label: string;
  type: 'text'|'number'|'date'|'datetime'|'boolean'|'select'|'multiselect';
  options?: { label, value, disabled? }[];   // select / multiselect
  operators?: string[];                       // restrict + order the operator list
  defaultOperator?: string; defaultValue?: unknown; placeholder?: string;
};

type RuleGroup = { id?; combinator: 'and'|'or'; not?: boolean; rules: (Rule|RuleGroup)[] };
type Rule = {
  id?; field: string; operator: string; value?: unknown;
  valueSource?: 'value' | 'field';   // 'field' → value holds another field's name
};

Accessibility

  • Each rule's field / operator / value carry aria-labels referencing the condition number; the combinator is a labeled ds-tab-filter (radiogroup semantics); a nested group is a labeled role="group" reading its combinator and NOT state.
  • Add / duplicate / remove are real <button>s with explicit labels; focus moves to the new row on add and to a neighbor on remove.
  • Validation errors render through ds-field-helper (role="alert") so they're announced; the invalid row also gets an error border (not colour alone — the helper states the problem).
  • Overlay modes set role="dialog" / aria-modal, move focus in on open and return it to the trigger on close, and dismiss on Esc (+ backdrop / outside click).
  • Design tokens only; works across all five themes and RTL. All DOM queries are scoped to the component root.
