Generating Pages with AI

Create new screens in the product by describing them in plain English — no code. You describe a page; the AI builds it from proven templates, styles it with Prism, and plugs it into the app shell so you can open it right away.

What it is

The product is two parts: the shell — the fixed frame of the app (top nav, side menus, theming) — and pages that fill the middle. Picture the shell as a framed wall with navigation, and each page as a picture you slot in. You ask for a picture; the AI paints it in the house style and hangs it for you.

How it works

the mental model

One shared shell

Every page runs inside the same app shell, so it automatically gets the header, menus, theme, and navigation.

Grouped by project

Pages live under projects/<name>/ — one project or task per folder keeps related screens together.

Built from templates

The AI starts from a proven pattern — form, list, detail, dashboard — and fills it with your content, so pages look consistent.

Opened by a short name

Each page gets a “slug” that names what it is (e.g. deployments) — that’s how you open it.

How to view a page

By URL

Add ?view=<slug> to the shell address, e.g. Shell.html?view=demo-deployments.

By clicking a tab

If a module tab is wired to the page (e.g. Software Deployment → the demo list), just click it.

In-flow

Pages link to each other — a form’s Save opens a list, a list row opens a detail, and so on.

To preview locally, run a small web server at the project root (python3 -m http.server 8790) and open http://localhost:8790/Layout/Shell.html. Opening files with file:// won’t work.

How to prompt for good results

the recipe

Mention as many of these as apply. Anything you leave out, the AI picks a sensible default or asks.

  1. Project / task nameWhich folder it belongs to — “under project acme”.
  2. What the page is forIts purpose in plain words. This becomes the slug and title.
  3. Which kind of pagePick an archetype — form, list, detail, dashboard — or let the AI choose.
  4. Where it livesWhich module/tab (Home, Configurations, Threats & Patches, Software Deployment, Inventory…). Optionally: “open it when I click that tab”.
  5. The important contentFields for a form; columns/KPIs for a list; sections for a detail; widgets for a dashboard.
  6. NavigationWhat actions do — “Save goes to the device list”, “a row opens the device detail”.

Good prompt examples

Form

“Under project acme, create a form page to configure a firewall rule, on the Configurations tab. Fields: rule name, direction, protocol, port range, action. On Save, go to the firewall rules list.”

List

“Add a list page called patch approvals under project acme, on Threats & Patches. Columns: patch name, severity badge, affected devices, status. KPI cards for Approved / Pending / Declined. Clicking a patch opens its detail.”

Dashboard

“Make a dashboard for project acme inventory overview, and open it when I click the Inventory tab. KPI tiles for total assets; charts for assets by OS and by warranty status.”

Vague vs. specific

Vague (AI has to guess)Specific (better output)
“Make a settings page.”“Under acme, a tabbed form for agent settings on Configurations, tabs General / Network / Security.”
“Add a list.”“A list managed devices on Inventory: columns device, platform, status badge, owner, last seen; row → device detail.”
“Build a dashboard.”“A dashboard security overview on Threats & Patches: KPI tiles (vulnerable, patched, at-risk) + a severity donut.”

Finish your prompt with “verify it in the browser” — the AI will load the page, click through it, and show you a screenshot before calling it done. Then iterate in plain language: “add a KPI row”, “make the header collapse on scroll”, “change Save to go to the deployments list”.

Tips & gotchas

  • Name by purpose, not template. “create-deployment”, “patch-approvals” — not “sectioned-form” or “list-view”. It’s what you type in the URL.
  • One project folder per feature/task keeps things tidy and easy to share.
  • Give real-ish sample content (field and column names). It makes the page instantly useful and easy to review.
  • Design consistency is automatic — pages use the shared components and tokens, so you don’t specify colors, fonts, or spacing.
  • Blank page? Just tell the AI — it’s usually a one-line wiring fix.
