# Projects

Per-project / per-task pages generated for the Prism shell live here, grouped by
project name:

```
projects/
  <project-name>/
    layout-<slug>.html      # a dual-mode view, same contract as Layout/views/layout-*.html
```

All projects run inside the **shared** shell (`Layout/Shell.html`). A project page is
registered in that shell's `CONTENT_VIEWS` router with a path that reaches out of
`Layout/`:

```js
'<project>-<slug>': { file: '../projects/<project>/layout-<slug>', tab: '<module-tab-id>' },
```

- The `file` value is a path **relative to `Shell.html`** (which sits in `Layout/`), so
  `../projects/...` resolves to this repo-root folder. The router's `injectDrawer` accepts
  any `file` containing a `/` as such a path.
- The router **slug** (map key) and the page's `window.ShellDrawers[...]` key must match and
  should be **project-prefixed** (e.g. `acme-agent-settings`) — slugs are global across the
  shared shell.

Open a project page injected in the shell via `Layout/Shell.html?view=<project>-<slug>`, or
standalone via `projects/<project>/layout-<slug>.html`.

Pages here are generated by the **`generate-layout`** skill — see
`.claude/skills/generate-layout/SKILL.md`.

## Worked example: `demo/`

`projects/demo/` is a reference implementation showing a three-page flow wired into the
shared shell (all on the `sd` / Software Deployment tab). Note the slugs name what each page
**is**, not the template it was built from:

- `layout-create-deployment.html` (`demo-create-deployment`) — Save & Continue → the list.
- `layout-deployments.html` (`demo-deployments`) — data table; a device link → the detail;
  "New Deployment" → back to the form.
- `layout-deployment-detail.html` (`demo-deployment-detail`) — record detail; "Back to list" → the list.

Try it: `Layout/Shell.html?view=demo-create-deployment` (or `demo-deployments` /
`demo-deployment-detail`), or open any file directly. Cross-view navigation uses
`window.openContentView('<slug>')`. Copy these as starting points for real project pages.
